### 0.1 콘텐츠 회사 배경 확정

엑스컴은 다음을 한 팀에서 수행하는 소형 콘텐츠 회사다.

- 브랜드·기관·지역의 이야기를 찾는 기획
- 자료조사·인터뷰·콘티·프리프로덕션
- 실사 촬영·현장 연출·소품·음향 수집
- 편집·색보정·모션그래픽·사운드
- 프로젝트별 기획·제작·편집·후반·최종 납품
- 원본·라이선스·크레딧·아카이브 관리

AI는 프리비즈, 합성 보조, 클린업 등 필요 구간에서만 쓰는 제작 도구다. 회사의 정체성과 게임의 승리 조건은 언제나 사람·장면·원본·완성본에 있다.

## 1. 하이 콘셉트

### 1.1 한 문장

플레이어는 입사 첫날부터 허파랑·이영림·이혜미·손미림과 함께 7일 안에 프로젝트를 납품해야 한다. 매일 아침 60초 안에 그날 필요한 장비와 문서를 챙기고, 낮에는 프로젝트를 진행하며, 밤 9시 57분 이후에는 삭제한 파일과 존재하지 않는 작업 기록이 되돌아오는 이면 스튜디오와 마주한다.

### 1.2 플레이어에게 던지는 질문

좋은 콘텐츠는 누가 만드는가?

가장 좋은 아이디어를 낸 사람인가.
현장을 끝까지 지킨 사람인가.
원본과 권리를 정리한 사람인가.
마지막 프레임을 닫은 사람인가.
아니면 그 모두가 사라지지 않도록 연결한 사람인가.

### 1.3 핵심 재미 네 축

1. **60초 제작 준비**
   오늘 촬영이 있는데 배터리를 챙길지, 동의서를 챙길지, SSD를 챙길지 선택한다. 필요한 물건을 놓친 대가는 반드시 낮이나 밤에 돌아온다.

2. **다섯 사람의 제작 배치**
   기획만 좋아도 영상은 안 나오고, 촬영만 많아도 이야기가 되지 않는다. 각 인물의 강점·컨디션·관계를 조합해 하루의 제작 공정을 설계한다.

3. **컨펌과 제작사고의 선택형 대응**
   "조금 더 감성적으로", "15초 버전도 오늘", "현장 화면 색이 다른데요" 같은 현실적인 압박을 예산·시간·신뢰·사람의 체력으로 막는다.

4. **밤 9시 57분의 장르 전환**
   낮에 편집하던 동일한 타임라인이 밤에는 다른 원본을 불러온다. 삭제한 테이크, 다섯 번째 목소리, 촬영하지 않은 장면이 창작의 출처를 묻는다.

### 1.4 차별점

이 게임에서 공포는 귀신이 갑자기 튀어나오는 데서 오지 않는다. 공포는 다음과 같은 제작 문법의 오작동에서 온다.

- 촬영하지 않은 파일에 정확한 카메라 메타데이터가 있다.
- 네 명만 있던 인터뷰 녹음에 다섯 번째 목소리가 있다.
- 삭제한 컷이 매일 더 길어진 채 돌아온다.
- 내일 촬영할 장소가 오늘의 러프컷에 들어 있다.
- 엔딩 크레딧에서 누군가의 이름이 한 글자씩 지워진다.
- 원본 폴더의 소유자가 SOURCE_0000 으로 바뀐다.

## 2. 회사와 프로젝트

### 2.1 ㈜엑스컴

엑스컴은 대형 프로덕션처럼 부서가 나뉘어 있지 않다. 한 사람이 아이디어를 내고, 다른 사람이 촬영 허가를 확인하며, 같은 날 누군가는 카메라를 들고 누군가는 편집 프로그램을 연다. 프로젝트마다 역할이 바뀌고, 모든 사람의 손을 거쳐야 최종본이 나온다.

**회사의 게임 내 정체성**

| 구분 | 내용 |
|---|---|
| 회사 유형 | 5인 규모의 콘텐츠 회사 |
| 주력 | 브랜드 필름, 지역문화 콘텐츠, 인터뷰, 숏폼, 공연·전시 상영물 |
| 강점 | 빠른 기획 전환, 현장 대응, 실사와 디지털 후반제작의 결합 |
| 약점 | 적은 인원, 역할 중첩, 원본·버전·컨펌 관리가 한 번 꼬이면 연쇄 붕괴 |
| 공간 | 사무실, 기획 회의실, 편집실, 미니 스튜디오, 장비실, 탕비실·아카이브 |
| 회사 모토 | "이야기는 끝까지 만들어야 이야기가 된다." |

본 설정은 게임을 위한 창작적 재구성이다. 실제 인물의 사생활·실제 거래처·실제 계약·실제 분쟁은 사용하지 않는다.

### 2.2 메인 프로젝트: 프로젝트 납품

엑스컴은 7일 안에 하나의 대형 프로젝트를 완성해 납품해야 한다. 게임에서는 발주처의 업종이나 프로젝트의 고유명, 구체적인 납품물을 특정하지 않고 모두 **"프로젝트"**라고만 부른다. 핵심은 무엇을 만드는지가 아니라, 촉박한 일정 속에서 다섯 사람이 기획·제작·검수·인수인계를 끝까지 연결하는 과정이다.

**프로젝트 표기 원칙**

게임 안에서는 프로젝트의 이름이나 업종을 별도로 붙이지 않는다. 모든 대사와 UI는 아래 표현으로 통일한다.

> "프로젝트 납품까지 D-7"

구체적인 산출물은 내부 제작 트랙으로만 관리하고, 플레이어에게는 하나의 프로젝트 완성도와 납품 가능 상태로 보여준다. 따라서 특정 축제·브랜드·영상 형식에 종속되지 않으며, 엑스컴의 실제 업무 분위기만 배경으로 사용한다.

### 2.3 왜 7일인가

프로젝트 폴더에는 이름 없는 파일, 절반만 정리된 자료, 비어 있는 기획안, 출처가 표시되지 않은 원본이 뒤섞여 있다. 엑스컴은 프로젝트를 다시 세우되, 기존 자료 중 무엇을 살리고 무엇을 버릴지 결정해야 한다.

첫날 밤, NAS에 없던 계정이 생성된다.

```
USER: SOURCE_0000
FOLDER: /PROJECT/DO_NOT_CREDIT/
LAST_LOGIN: 21:57
```

### 2.4 이면 스튜디오

밤 9시 57분이 되면 모든 모니터의 타임코드가 21:57:00:00 으로 고정된다. 편집 재생헤드는 스스로 뒤로 움직이고, 미니 스튜디오의 REC 등이 켜진다. 낮과 같은 공간이지만 규칙이 다르다.

이면 스튜디오는 한 명의 악령이 만든 곳이 아니다. 다음이 오랫동안 쌓여 하나의 제작 주체처럼 변한 장소다.

- 이름 없이 사용된 원본
- 크레딧에서 빠진 사람
- 전달되지 않은 인수인계
- "최종"이라는 이름만 남은 미완성본
- 저장되지 않은 수정
- 누구도 책임지지 않은 파일
- 끝내 공개되지 못한 장면

그 집합체가 SOURCE_0000 이다.

### 2.5 타임루프

납품에 실패하거나 플레이어가 이면 스튜디오에 흡수되면 NAS가 자동 복구를 실행한다.

```
RESTORE POINT FOUND
D-7_MASTER.backup
복원하시겠습니까?
```

플레이어만 이전 루프를 기억한다. 다른 네 사람은 설명할 수 없는 익숙함, 미리 적어 둔 체크리스트, 이미 본 듯한 장면으로 루프의 흔적을 드러낸다.

## 3. 등장인물

### 3.1 공통 규칙

- 인물은 집중력, 체력, 유대도를 가진다.
- 집중력 또는 체력이 낮으면 실수가 증가하고 특기가 약화된다.
- 유대도 30/60/90에서 개인 이벤트가 열린다.
- 실명은 사용하되 역할과 사건은 게임용 창작이다.
- 플레이어를 포함한 다섯 명 모두 제작의 주체다. 누구도 단순 보조 NPC가 아니다.

#### 유대도 정본 (v4.0 신설)

유대도는 0~100의 수치로, 전원 초기값 20에서 시작한다. 30/60/90 도달 시 해당 인물의 개인 이벤트 1/2/3단계가 열린다. 단계 이벤트는 런당 1회, 하루 1건까지 발생한다.

| 항목 | 내용 |
| --- | --- |
| 범위 / 초기값 | 0~100 / 20 |
| 단계 개방 | 30 → 1단계, 60 → 2단계, 90 → 3단계 |
| 획득 — 개인 관련 이벤트 선택 | 해당 인물을 지지·조력하는 선택 시 +3~+5 |
| 획득 — '스튜디오 컷' 콤보 | 전원 +3 (4.2 참조) |
| 획득 — 개인 아크 분기 | 9.2 인물별 7일 아크의 분기 선택 시 +5 |

플레이어는 유대도 이벤트 체인 대신 SOURCE_0000과의 '추적 단계' 3단계를 가진다(3.6 참조). 추적 단계는 11.4 진엔딩 체인의 진행 상태를 플레이어 개인 아크로 표면화한 것이다.

- 선택 B "격리 백업부터.": 원본 무결성 +3, 유대도 +3

- 편집·후반 80 이상
- 마스터·납품 75 이상
- 원본 무결성 65 이상

```
납품 점수 =
  기획·서사 × 0.20
+ 촬영·원본 × 0.25
+ 편집·후반 × 0.25
```

### 5.4 실패는 무엇을 뜻하는가

이 게임은 과로를 정답으로 만들지 않는다. 야근은 빠른 진척을 주지만 다음 날 집중력·체력·원본 무결성을 훼손하고, 밤의 괴이를 불러온다. 가장 좋은 엔딩은 "가장 많이 남은 팀"이 아니라 범위를 잠그고, 기록을 공유하고, 원본을 추적해, 해 지기 전에 마스터를 닫은 팀이 얻는다.

#### 페이즈 5 컨펌 판정(v4.0 신설)

컨펌은 D-6부터 매일 1회 실시한다. D-4의 컨펌은 중간 컨펌으로 취급하며 결과가 2배 가중된다.

```
컨펌 성공률 = 55%
 + (기획·서사 ÷ 4)%p
 + (클라이언트 신뢰 − 50) × 0.4%p
 − (수정 부채 ÷ 2)%p
```

- 성공률은 5~95%로 한정한다.
- 이영림 액티브, 페어 '브리프 잠금'(+20%p) 등 기존 보정이 위 식에 합산된다.

| 결과 | 효과 |
|---|---|
| 성공 | 클라이언트 신뢰 +3 |
| 실패 | 수정 부채 +4, 클라이언트 신뢰 -3 |
| 2회 연속 실패 | 상태이상 '컨펌 공포' 부여(6.3 참조) |
| 중간 컨펌(D-4) 성공 | 클라이언트 신뢰 +6 |
| 중간 컨펌(D-4) 실패 | 수정 부채 +8 |

예시. D-6 저녁, 기획·서사 24, 신뢰 50, 수정 부채 0이면 55 + 6 + 0 − 0 = 61%. 같은 날 페어 '브리프 잠금'을 성립시켰다면 81%.

```
개인 산출 =
  해당 능력치

```

```

```

#### 업무 판정(v4.0 신설)

배치된 업무는 기본적으로 성공한다. 산출 확정 직전에 크리티컬과 실수를 순서대로 1회씩 판정한다.

크리티컬

```
크리티컬 확률 = 10%
 + 적합 인물 배치 5%p
 + 요구 장비 완비 5%p
 + 페어 시너지 명시 효과
 + 전공 보정
```

- 전공 보정: 수행자의 슬롯 대응 능력치(기획·구성=기획, 프리프로덕션=제작관리, 촬영·현장=연출, 편집·모션·최종 납품 QC=후반)가 9 이상이면 +5%p. 플레이어는 능력치가 전부 6이므로 이 기준 대신, 선택한 전공과 일치하는 슬롯에서 +5%p를 받는다(3.6 전공 참조).
- 크리티컬 확률 상한은 40%다. 크리티컬 시 해당 카드의 크리티컬 결과를 성공 결과에 추가 적용한다.

실수(제작사고)

```
실수 확률 = 5%
 + 수행자 집중 또는 체력 40 미만 10%p
 + 수행자 집중 또는 체력 25 미만 20%p (40 미만 보정 대체)
 + 요구 장비 미비 15%p
```

- 실수 확률 상한은 60%다. 실수 시 해당 카드의 실패 결과를 적용하며, 실패 결과가 명시되지 않은 카드는 산출 절반 + 수정 부채 +2로 처리한다.
- 크리티컬과 실수가 동시에 나오면 실수가 우선한다.
- 8.3의 정리·회복 배치 보정(다음 날 숨은 실수 확률 -10%p)은 이 실수 확률에서 차감한다.

- 같은 인물이 2일 연속 같은 고강도 슬롯을 수행하면 소모 +3
- 정리·회복에 배치된 인물은 다음 날 숨은 실수 확률 -10%p

## 9.5 밸런스 검산

이 장은 5~8장의 확정 수치(자원, 산출 공식, 업무 카드, 판정, 야근, 게이트)를 그대로 사용해 표준 7일 런 3종을 손으로 계산하고, 설계 목표가 산술적으로 성립하는지 확인한다. v3.1 원전 수치는 어느 것도 바꾸지 않는다. 미달·과잉이 발견된 항목은 9.5.3의 튜닝 권고 표에 권고로만 남긴다.

### 9.5.1 검산 전제

원전이 명시한 공식은 그대로 쓰고, 원전이 결합 방법을 명시하지 않은 지점은 아래 해석을 고정해 계산했다. 해석이 필요했다는 사실 자체가 튜닝 권고 대상이다(9.5.3 권고 1).

**산출 결합 규칙(검산 해석)**

```
슬롯 실행 1회의 트랙 증가
= Σ 수행자 개인 산출            → 슬롯 주요 트랙에 적립
+ 배치 카드의 성공값·부가 효과   → 카드에 명시된 트랙·자원에 적립

개인 산출 = 해당 능력치 × (0.5 + 0.005 × min(집중력, 체력)) × 장비·시너지 보정
```

- 슬롯 주요 트랙과 대응 능력치: 기획·구성→기획·서사(기획), 프리프로덕션→기획·서사(제작관리), 촬영·현장→촬영·원본(연출), 편집·모션→편집·후반(후반), 최종 납품 QC→마스터·납품(후반).
- 컨디션 계수는 그날 아침(배치 시점) 값. 슬롯 소모는 산출 확정 후 적용.
- 야근 실행은 산출·카드값 모두 ×0.65(6.2).

**고정 전제**

1. 크리티컬·실수·현실 제작 이벤트·괴이 보상의 확률 항은 0으로 고정한 '기대 중립 검산'이다. 리스크는 각 표 아래 별도 행으로 기재한다.
2. 마일스톤 카드(브리프 잠금, 콘티, 부두 촬영, 러프컷, 파인컷, 버전 잠금, 마스터링, 최종 납품본 QC, 중간 컨펌 준비)는 런당 1회, 나머지 카드는 반복 실행 가능으로 본다.
3. 컨펌은 계산된 성공률이 50% 이상이면 성공으로 처리한다(기대값 근사). 실제 성공률 수치는 검산 근거에 병기한다.
4. 트랙·무결성·신뢰 상한 100, 부채 상한 60, 부채 하한 0.
5. 페어·콤보·패시브·액티브는 명시된 수치 효과만 반영한다. 이영림 패시브는 '이영림이 참여한 기획 획득의 20%를 관객 공감으로 전환(기획은 80% 적립)', 플레이어 패시브는 '주 트랙 획득의 15% 사본을 다음 공정 트랙에 전달'로 해석했다.
6. 공포는 매일 밤 이면 조우율(6.2)×조우당 평균 공포 +6(ⓒ는 저컨디션 담력 판정 실패 기대를 반영해 +12)의 기대치로 적산하고, '기록 공유'(−5/일)는 사용 시나리오에만 적용한다.
7. 야근일 밤에는 조우율×4의 원본 무결성 기대 손실을 적용한다(5.4의 "야근은 원본 무결성을 훼손한다"의 임시 수치화 — 권고 5).
8. 커피 보급은 IT-28 믹스커피 박스를 스크램블에서 격일 2회 확보(+10)로 전제한다.

- 공포 리스크: 기대 적산은 7.9지만, 조우율 41~66%에서 조우가 실제로 발생하면 담력 판정(집중 0~10 기준 성공률 52~55%)의 실패 확률이 절반이고, 실패당 공포 +10~15와 상태이상(타임코드 오염, 다섯 번째 채널 등)이 쌓인다. 상방 시나리오에서 공포 40~70.
- 집중 붕괴 리스크: D-2에 손미림, D-1에 플레이어까지 집중 0 도달. 집중 붕괴의 임계가 원전에 미정의지만(권고 7), '집중 0 = 붕괴'로 읽으면 D-1에 3명째가 무너지는 순간 **ED-10 전원 오프라인 즉시 실패**다. 손미림 과부하 '렌더 대기'(25%)도 D-4부터 상시 발동권이다.
- 무결성 81.3은 백업·권리 카드 반복 덕이며, 야간 기대 손실 전제(조우율×4)만 반영한 낙관치다. 백업 실수 1회(−5)와 GH 악결과가 겹치면 65 게이트가 위협받는다.

### 9.5.6 D-0 납품 점수 공식 검산 — ⓑ 라인

ⓑ 최종 수치: 기획·서사 100.0, 촬영·원본 89.3, 편집·후반 94.0, 마스터·납품 87.1, 원본 무결성 100.0, 클라이언트 신뢰 71, 수정 부채 0, 관객 공감 19.1.

|---|---|---|---|
| 1 | 기획·서사 × 0.20 | 100.0 × 0.20 = 20.00 | 20.00 |
| 2 | 촬영·원본 × 0.25 | 89.3 × 0.25 = 22.33 | 42.33 |
| 3 | 편집·후반 × 0.25 | 94.0 × 0.25 = 23.50 | 65.83 |
| 4 | 마스터·납품 × 0.15 | 87.1 × 0.15 = 13.07 | 78.90 |
| 5 | 원본 무결성 × 0.10 | 100.0 × 0.10 = 10.00 | 88.90 |
| 6 | 클라이언트 신뢰 × 0.05 | 71 × 0.05 = 3.55 | 92.45 |
| 7 | 수정 부채 × 0.35 차감 | 0 × 0.35 = 0.00 | 92.45 |

최종 92.4 → **85~94 좋은 납품**. 전원 잔류 시 ED-02 '다음 프로젝트도 함께'. ED-03(95 이상)은 점수 2.6 부족으로 미달 — 야근 2회 이하·무결성 90 이상 조건은 이미 충족하므로, ED-03은 크리티컬·관객 공감 보정 같은 확률 상방을 잡은 런의 몫이다. 리스크 반영 하한(83)에서도 75선을 방어하므로, ⓑ 라인의 실전 결과는 ED-01~ED-02 사이에서 진동한다. 이것이 "턱걸이~좋은 납품"의 산술적 실체다.

### 11.2 야간 플레이

플레이어는 동일한 사무실을 직접 이동한다.

**목표**

- 내 책상의 프로젝트 종료 버튼까지 돌아오기
- 괴이를 회피·조사·협상
- 메타데이터 조각, 원본 로그, 크레딧 단서 획득
- 욕심을 내면 낮 제작에 큰 보상을 얻지만 공포와 오염이 증가

**공포 판정**

```
담력 성공률 =
  65%
+ 플레이어 집중력 보정
+ 도감 보정
+ 원본 무결성 보정
- 공포 ÷ 4
- 수정 부채 ÷ 3
```

각 계수는 다음과 같이 확정한다.

| 항목 | 값 |
|---|---|
| 기본치 | 65% |
| 집중력 보정 | (플레이어 집중력 − 50) ÷ 5 %p |
| 도감 보정 | 해당 괴이가 이면 프레임 도감에 등록되어 있으면 +15%p |
| 원본 무결성 보정 | 원본 무결성 80 이상 +10%p / 40 미만 −10%p / 그 외 0 |
| 공포 감산 | − 공포 ÷ 4 %p |
| 수정 부채 감산 | − 수정 부채 ÷ 3 %p |

최종 성공률은 5%~95%로 클램프한다.

예시: 집중 60, 도감 등록, 무결성 82, 공포 20, 수정 부채 12 → 65 + 2 + 15 + 10 − 5 − 4 = 83%.

- 도감 등록 조건: '버전 비교'를 완료.

#### GH-04 다섯 번째 목소리

네 명만 있던 회의 녹음에 다섯 번째 사람이 말한다.

> "그 장면은 내 거예요."

- 출현 조건: D-6~D-2. 당일까지 회의·인터뷰 녹음 파일이 1개 이상 존재(기본 충족).
- 노이즈로 제거: 마스터 +3, 다섯 번째 채널 위험
- 답변 녹음: 공포 +10, 크레딧 단서 — **크레딧 장부 조각(1/3) 획득처**
- 룸톤 재생: 무선 마이크·헤드폰 보유 시 안전하게 분리
- 실패 정의: '답변 녹음'이 담력 판정, '노이즈로 제거'가 명시 리스크다. 어느 쪽이든 실패 시 상태이상 **'다섯 번째 채널'**(모든 녹음에 미지 음성 혼입, 해제: 룸톤 의식 또는 원본 로그).
- 도감 등록 조건: '룸톤 재생' 성공 또는 '답변 녹음' 완료.

#### GH-05 촬영하지 않은 장면

타임라인에 촬영한 적 없는 새벽 장면이 들어 있다. 촬영 날짜는 내일, 카메라 시리얼은 등록되지 않았다.

- 출현 조건: D-5~D-2. 촬영·원본 진척 20 이상.
- 사용: 촬영 +12, 원본 무결성 -15
- 삭제: 관객 공감 -3
- 보류하고 출처 추적: 진엔딩 플래그 +1
- 실패 정의: '보류하고 출처 추적'이 담력 판정, '사용'이 명시 리스크다. 실패 시 상태이상 **'동행 컷'**(플레이어 뒤에 미지 인물 스프라이트, 해제: 해당 컷 삭제 대신 출처 확인).
- 도감 등록 조건: '보류하고 출처 추적'을 완료.

#### GH-06 빈 슬레이트

미니 스튜디오에서 슬레이트가 혼자 닫힌다. 장면·컷·테이크 칸이 비어 있고, 촬영자 칸에 플레이어 이름이 적힌다.

- 출현 조건: D-6~D-2. 야간에 미니 스튜디오 구역 진입 시.
- 이름 지우기: 집중 -10
- 장면 번호 쓰기: 다음 날 해당 장면 확정 촬영
- SOURCE_0000 쓰기: GH-09 출현률 증가
- 실패 정의: 'SOURCE_0000 쓰기'가 담력 판정이다. 실패 시 GH-09 출현률 증가 없이 공포 +8, '타임코드 오염' 판정.
- 도감 등록 조건: '장면 번호 쓰기' 또는 'SOURCE_0000 쓰기'를 완료.

#### GH-07 역재생 인터뷰

인터뷰이가 입을 닫은 채 말한다. 역재생하면 질문이 들린다. 그 질문은 아직 이영림이 쓰지 않은 문장이다.

- 출현 조건: D-5~D-2. 촬영·원본 진척 30 이상(인터뷰 촬영 이력 필요).
- 질문 기록: 기획 +5, 다음 날 이영림 집중 -5 — '질문 기록'은 크레딧 장부 조각이 아니라 **원본 로그 단서**로 집계된다.
- 파일 닫기: 안전
- 대답 녹음: 관객 공감 +8, 공포 +15
- 실패 정의: '대답 녹음'이 담력 판정이다. 실패 시 공감 획득 없이 공포 +15만 적용, '타임코드 오염' 판정.
- 도감 등록 조건: '질문 기록' 또는 '대답 녹음'을 완료.

#### GH-08 4층 로케이션

3층짜리 건물의 엘리베이터에 4층 버튼이 생긴다. 문이 열리면 동일한 엑스컴 사무실이지만 책상마다 다른 시대의 편집 장비가 놓여 있다.

- 출현 조건: IT-30 '이름 없는 미니DV 테이프' 소지 시에만 4층 버튼이 생성된다. D-6부터 가능, 권장 D-5. 재조우 가능.
- 진입: 원본 로그 탐색
- 버튼 제거: 괴이 1회 격퇴 아이템
- 이름 없는 미니DV 태그: GH-14 체인 개방
- 실패 정의: '진입' 후의 4층 탐색이 담력 판정이다. 실패 시 원본 로그 미획득, 공포 +10, '타임코드 오염' 판정.
- 도감 등록 조건: 4층에 1회 '진입'.

#### GH-09 SOURCE_0000

NAS 사용자 목록에 다섯 명 외 계정이 로그인한다. 채팅창이 열린다.

> "사용할 거면 이름을 남겨주세요."

- 출현 조건: D-5~D-1. GH-08 '진입' 이후 조우 테이블에 등재. GH-06 'SOURCE_0000 쓰기'로 출현률이 증가한다.
- 로그아웃 강제: 공포 +15
- 누구인지 묻기: 크레딧 장부 조각 — **크레딧 장부 조각(2/3) 획득처**
- 프로젝트 소유권 공유: 원본 무결성 +8, 야간 오염 증가
- 실패 정의: '누구인지 묻기'가 담력 판정이다. 실패 시 조각 미획득, 공포 +12, '타임코드 오염' 판정. 진엔딩 체인 진행을 위해 재조우로 재시도할 수 있다.
- 도감 등록 조건: '누구인지 묻기'를 완료(성공·실패 무관).

#### GH-10 내일의 렌더

렌더 큐 00번이 완료된다. 파일에는 내일 발생할 컨펌 장면과, 그 뒤 빈 책상 하나가 들어 있다.

- 출현 조건: D-5~D-2. 편집·후반 진척 30 이상(렌더 대기열이 존재해야 한다).
- 삭제: 다음 이벤트 숨김
- 시청: 다음 이벤트 결과 공개, 공포 +10
- 다른 선택을 촬영: 다음 날 이벤트 1회 재선택 가능
- 실패 정의: '시청'이 담력 판정이다. 실패 시 상태이상 **'렌더 루프'**(결산 때 후반 진척 일부 되돌아감, 해제: 렌더 큐 00번 완료).
- 도감 등록 조건: '시청'을 완료.

#### GH-11 00:00:00:00

모든 영상의 시작 타임코드가 0으로 바뀌고 컷 순서가 섞인다.

- 출현 조건: D-4~D-1. 편집·후반 진척 40 이상 또는 수정 부채 15 이상.
- 자동 정렬: 50% 성공
- 슬레이트 로그 수동 대조: IT-18 보유 시 성공
- 섞인 순서로 재생: 새로운 편집 +8, 기획 -5
- 실패 정의: '자동 정렬'의 50% 실패가 악결과다. 실패 시 컷 순서가 섞인 채 남아 다음 날 편집·모션 슬롯 산출 ×0.8, '타임코드 오염' 판정.
- 도감 등록 조건: '슬레이트 로그 수동 대조' 성공 또는 '섞인 순서로 재생' 완료.

#### GH-12 승인된 적 없는 컷

발주처 이름으로 승인 완료 도장이 찍혀 있다. 메일·메신저·회의록에는 기록이 없다.

- 출현 조건: D-4~D-1. 컨펌(하루 페이즈 5)을 1회 이상 수행한 뒤.
- 승인으로 간주: 신뢰 +5, D-0 발각 위험
- 무효 처리: 마스터 -3
- 승인 로그 요청: 이혜미 유대도 60이면 숨은 진실 획득 — **크레딧 장부 조각(3/3) 획득처**
- 실패 정의: '승인으로 간주'의 D-0 발각(발각률 40%)이 명시 리스크의 악결과다. 발각 시 클라이언트 신뢰 -10, 수정 부채 +8.
- 도감 등록 조건: '승인 로그 요청'을 수행(유대도 충족 여부 무관).

#### GH-13 월화수목금금금

캘린더의 토·일이 금요일로 바뀌고, 편집 타임라인이 7개의 금요일로 늘어난다.

- 출현 조건: D-4~D-2. 야근 누적 3회 이상.
- 연차신청서 제시: 휴일 조각 획득
- "오늘은 끝냅니다": 야근 즉시 종료, 전원 집중 +5
- 계속 렌더: 후반 +10, 전원 프레임 드롭
- 실패 정의: 담력 판정 없음. '계속 렌더'의 전원 프레임 드롭(다음 날 전원 집중 -10)이 명시 리스크의 악결과이며 '타임코드 오염' 판정.
- 도감 등록 조건: '연차신청서 제시'로 휴일 조각을 획득.

#### GH-14 원본 작성자

4층 아카이브에서 이름이 지워진 크레딧 시트가 나온다. 한 줄씩 복원할 때마다 낮의 좋은 컷 하나가 사라진다.

- 출현 조건: GH-08 '이름 없는 미니DV 태그'로 체인 개방 후, 4층 아카이브 진입 시. 권장 일차 D-2~D-1.
- 전부 복원: 진척 합계 -10, 진엔딩 체인
- 필요한 이름만 복원: 진척 -3, 일반 굿엔딩
- 덮기: 원본 무결성 -20, 촬영 +10
- 실패 정의: '전부 복원'이 담력 판정, '덮기'가 명시 리스크다. 실패 시 상태이상 **'크레딧 소실'**(유대도 보너스 무효, 해제: 원본·권리 목록 완성).
- 도감 등록 조건: 크레딧 시트를 1줄 이상 복원.

#### GH-15 마스터 인계

D-1, GH-09와 GH-14를 완료하고 원본·권리 목록이 80% 이상이면 발생한다. SOURCE_0000 이 최종 작업본을 연다.

> "마지막 프레임의 소유자를 지정하세요."

- 출현 조건: 원전 명시 조건 유지 — D-1, GH-09·GH-14 완료 + 원본·권리 목록 80% 이상. 조건 미달 시 이번 루프에서는 출현하지 않는다.
- 엑스컴: 일반 성공, SOURCE 잔류
- 발주처: 신뢰 +10, 원본 무결성 -10
- 제작자 전원과 출처를 기록: 진엔딩 플래그 TRACEABLE_MASTER
- 아무도 지정하지 않음: ED-09
- 실패 정의: 담력 판정 없음. '아무도 지정하지 않음'이 악결과이며 즉시 ED-09로 분기한다.
- 도감 등록 조건: 조우 즉시 등록(1회성 이벤트).

**크레딧 장부 조각 획득처(총 3곳)**

| 조각 | 괴이 | 선택지 | 전제 |
|---|---|---|---|
| 1/3 | GH-04 다섯 번째 목소리 | 답변 녹음 | 공포 +10 감수 |
| 2/3 | GH-09 SOURCE_0000 | 누구인지 묻기 | 담력 판정 성공 |
| 3/3 | GH-12 승인된 적 없는 컷 | 승인 로그 요청 | 이혜미 유대도 60 |

GH-07 '질문 기록'은 크레딧 장부 조각이 아니라 원본 로그 단서다. 조각과 혼동하지 않도록 UI에서 별도 아이콘으로 표시한다.

### 11.4 진엔딩 체인

```
IT-30 이름 없는 미니DV
        ↓
GH-08 4층 로케이션
        ↓
GH-09 SOURCE_0000
        ↓
크레딧 장부 3조각 + 원본·권리 목록 80%
        ↓
GH-14 원본 작성자
        ↓
GH-15 마스터 인계
        ↓
TRACEABLE_MASTER
        ↓
D-0 프로젝트 납품 성공
        ↓

```

**일차별 권장 진행표**

| 일차 | 목표 | 비고 |
|---|---|---|
| D-6 | IT-30 '이름 없는 미니DV 테이프' 확보 | 탕비실·아카이브의 구형 테이프 더미에서 획득. 야간 탐색 또는 60초 스크램블로 확보 가능 |
| D-5 | GH-08 조우 | '이름 없는 미니DV 태그'로 GH-14 체인 개방 + '진입'까지 완료(재조우 포함) — GH-09 등재 전제가 'GH-08 진입 이후'이므로 두 선택 모두 마쳐야 D-4 계획이 성립한다 |
| D-4 | GH-09 조우 | '누구인지 묻기'로 조각 2/3. 실패 시 D-3에 재시도 |
| D-3~D-2 | 조각 수집·원본·권리 목록 진행 | GH-04(조각 1/3)·GH-12(조각 3/3, 이혜미 유대도 60 필요) 처리. 원본·권리 목록 80% 달성 |
| D-1 | GH-14 → GH-15 | GH-14 '전부 복원'(진척 합계 -10 감수) 후 GH-15에서 '제작자 전원과 출처를 기록' 선택. TRACEABLE_MASTER 획득 |
| D-0 | 프로젝트 납품 성공 | D-0 게이트 통과 시 ED-11 |

운영 유의점.

- 이혜미 유대도 60은 D-2까지 확보해야 GH-12 조각을 놓치지 않는다. 유대도 획득 수단은 개인 이벤트·'스튜디오 컷' 콤보(+3)·개인 아크 분기.
- GH-14 '전부 복원'의 진척 합계 -10은 D-0 게이트(80/85/80/75)를 위협하므로, D-2까지 각 트랙에 10 이상의 여유를 확보해 두는 것을 권장한다.
- 「무압축」 난이도는 복원(루프) 3회 제한이 있으므로, 위 진행표에서 하루라도 어긋나면 진엔딩보다 납품 안정화를 우선한다.

## 12. 엔딩 12종

각 엔딩에는 v4.0 신설 열 '리테이크 노트 보상'이 붙는다. 이 보상은 해당 엔딩을 **최초 달성한 런**에서 13.1 획득식의 '새 엔딩 × 40' 항목 대신 지급되는 엔딩별 차등값이다. 이미 본 엔딩을 다시 보면 지급되지 않는다. 스케일: 배드 20~40 / 일반 성공 60~80 / 특수 100 / 진엔딩 150.

| ID | 엔딩 | 조건 | 결과 | 리테이크 노트 보상 |

### 12.1 진엔딩 연출

납품 직전, 최종 크레딧이 열린다. 처음에는 허파랑·이영림·이혜미·손미림·플레이어의 이름만 나온다. 이어 원본 제공자, 참여자, 협조자, 음악·폰트·자료 출처, 이전 작업자가 한 줄씩 복원된다.

마지막 줄:

```
SOURCE_0000
→ SOURCE MANIFEST COMPLETE
```

편집실 시계가 21:56에서 21:58로 넘어간다. 21:57 전환은 발생하지 않는다.

허파랑이 모니터를 끈다.

> "끝난 게 아니라, 제대로 넘긴 거야."

타이틀:

> 진엔딩 — 모든 장면에는 만든 사람이 있다

### 12.2 엔딩 우선순위

2. D-0 기술 실패형: ED-06, ED-07, ED-08

## 13. 로그라이크 메타 진행

### 13.1 메타 재화 — 리테이크 노트

한 런이 끝나면 플레이어가 다음을 기록한다.

- 잘못 챙긴 물건
- 놓친 컷
- 발생한 제작사고
- 발견한 괴이
- 본 엔딩
- 끝내 확인하지 못한 출처

이 기록이 **리테이크 노트**가 되어 다음 루프의 제작 시스템을 개선한다.

#### 획득식

```
리테이크 노트 =
  도달 일차 × 8
+ 최종 납품 점수
+ 신규 괴이 도감 × 12
+ 새 엔딩 × 40
+ 원본 무결성 ÷ 2
```

v4.0 보정 두 가지. ① '새 엔딩 × 40'은 기준값이며, 최초 달성 엔딩은 12장 보상표의 차등값(20~150)으로 대체 지급된다. ② 합계에 난이도 배율을 곱한다: 가편집 ×0.8 / 본편집 ×1.0 / 감독판 ×1.25 / 무압축 ×1.6. 도달 일차는 D-7을 1일차, D-0을 8일차로 센다.

### 13.5 리테이크 노트 이코노미 (v4.0 신설)

메타 진행 곡선의 목표는 본편집(노멀) 기준 10~12런 안에 전 모듈 완주다. 아래 수치는 시뮬 검증 대상이다. 모든 계산은 본편집(배율 ×1.0) 기준이다.

#### 런당 기대 획득량 — 실패 런

초반 탐색 실패 런 예시. D-3에서 런이 끝나고(5일차), ED-08을 처음 본 경우.

| 항목 | 값 | 획득 |
|---|---|---|
| 도달 일차 × 8 | 5일차(D-3) | 40 |
| 최종 납품 점수 | 납품 실패 | 0 |
| 신규 괴이 도감 × 12 | 2종 | 24 |
| 새 엔딩 보상 | ED-08 최초 | 30 |
| 원본 무결성 ÷ 2 | 42 | 21 |
| **합계** | | **115** |

숙련 후 실패 런(신규 도감·새 엔딩 없음, 무결성 40 내외)은 약 60이다. 실패 런의 기대 획득량은 **60~120**으로 잡는다.

#### 런당 기대 획득량 — 성공 런

일반 성공 런 예시. D-0 납품(8일차), 점수 85, ED-02를 처음 본 경우.

| 항목 | 값 | 획득 |
|---|---|---|
| 도달 일차 × 8 | 8일차(D-0) | 64 |
| 최종 납품 점수 | 85 | 85 |
| 신규 괴이 도감 × 12 | 1종 | 12 |
| 새 엔딩 보상 | ED-02 최초 | 70 |
| 원본 무결성 ÷ 2 | 82 | 41 |
| **합계** | | **272** |

숙련 반복 성공 런(신규 요소 없음)은 64 + 85 + 0 + 0 + 41 = **약 190**. 진엔딩 런(점수 92, 무결성 90, 신규 괴이 2종, ED-11 최초)은 64 + 92 + 24 + 150 + 45 = **375**로 단일 런 최대치다.

#### 전 모듈 완주 총비용과 기대 런 수

모듈 16종 비용 합계: 40+60+50+80+90+70+100+90+110+120+130+140+150+160+180+220 = **1,790**.

기대 런 수 계산(본편집). 1~3런은 실패 위주로 평균 115씩 총 345, 4런차부터는 성공 위주로 평균 210(신규 엔딩 포함 272와 숙련 190의 혼합)을 가정한다. (1,790 − 345) ÷ 210 ≈ 6.9 → 7런. 따라서 완주까지 **약 10런**, 실패가 섞이면 10~12런이다. 목표 곡선과 일치한다.

| 난이도 | 배율 | 기대 완주 런 수 |
|---|---|---|
| 가편집 | ×0.8 | 약 13런 |
| 본편집 | ×1.0 | 약 10~12런 |
| 감독판 | ×1.25 | 약 8~9런 |
| 무압축 | ×1.6 | 약 6~7런 (복원 3회 제한 리스크 포함) |

#### 구매 순서 추천 트리

```
1런차 종료(~115)   PK-01 아침 장비 체크(40) + PK-03 예비 배터리(50)
2런차 종료(~230)   PK-02 큰 장비가방(60) + PK-06 동의서 체크(70)
3~4런차(~345+)     PK-04 버전 네이밍 규칙(80) → PK-08 회의록 한 페이지(90)
5~6런차            플레이스타일 분기(택1 우선)
                    ├─ 안정형: PK-07 3-2-1 백업(100) → PK-09 드롭프레임 탐지(110) → PK-10 납품 프리셋(120)
                    ├─ 점수형: PK-05 쇼트리스트 템플릿(90) → PK-11 사람 검수(130) → PK-12 스코프 잠금(140)
                    └─ 무야근형: PK-13 무야근 캘린더(150) — ED-12 '해 지기 전에' 노림
7런차 이후          PK-15 전체 회고(180) → PK-14 크레딧 메타데이터(160) → PK-16 소스 감사(220)
                    — 진엔딩 체인(GH-14 → GH-15 → TRACEABLE_MASTER → ED-11) 마무리 지원
```

설계 의도. 1~2런차에 생존 기반(장비·인벤토리·배터리·권리)을 깔고, 3~4런차에 수정 부채 관리로 게이트 통과율을 올린다. 5~6런차 분기는 플레이어가 노리는 엔딩 계열에 따라 갈라지며, 진엔딩 지원 모듈(PK-14, PK-16)은 가장 비싸고 가장 늦다. PK-16 소스 감사는 최후 구매로 두어 첫 진엔딩 도전의 탐색 재미를 해치지 않게 한다.

## 15. 화면과 UX

### 15.1 타이틀

편집 프로그램 타임라인처럼 구성한다.

```
 V1   [D-7] [D-6] [D-5] [D-4] [D-3] [D-2] [D-1] [D-0]
 A1   ─────────────────────────────────────────────
       프로젝트 열기 / 이어서 편집 / 리테이크 노트 / 도감 / 설정
```

메뉴 커서는 재생헤드다. 실제 시각 21:57에 타이틀을 열면 빈 V2 트랙에 SOURCE_0000 클립이 1초 나타난다.

### 15.2 스크램블 HUD

- 상단 중앙: 60초 타임코드
- 좌상단: 오늘 촬영·업무
- 하단: 장비가방 8칸
- 아이템 테두리:
  - 문서: 사각 라벨
  - 장비: 원형 REC
  - 권리·원본: 체인 링크
  - 이면: 깨진 타임코드

### 15.3 업무 배치

상단에 네 제작 트랙이 가로로 놓인다.

```
 기획·서사 | 제작·원본 | 편집·후반 | 마스터·납품
```

좌측에 인물 카드, 중앙에 6개 업무 슬롯, 우측에 오늘의 촬영 조건·컨펌 일정·치명 누락이 표시된다.

### 15.4 이벤트 카드

현실 이벤트는 제작 문서 카드, 이면 이벤트는 손상된 영상 클립 카드다.

- 현실: 선택 전 예상 자원 종류만 표시
- 정보 모듈 보유: 구체 수치 표시
- 이면: 선택지 텍스트 일부가 한 프레임씩 다른 문장으로 바뀜
- 접근성 모드: 문장 변조를 정적 아이콘으로 대체

### 15.5 제작일보

결산은 제작일보 + 타임라인 변경 로그다.

| 영역 | 표시 |
|---|---|
| 오늘 확보한 컷 | 촬영·원본 변화 |
| 오늘 닫은 문장 | 기획·서사 변화 |
| 오늘 만든 버전 | 편집·후반 변화 |
| 오늘 확인한 규격 | 마스터·납품 변화 |
| 미해결 | 권리·원본·컨펌·렌더 |
| 사람 | 집중력·체력·유대도 |
| 밤 | 발견한 메타데이터와 공포 |

### 15.6 접근성

- 플래시 감소
- 화면 흔들림 제거
- 공포 연출 완화
- 자막 크기 3단계
- 고대비 타임라인
- 색각 보조 아이콘
- 60초 → 90초 보조 모드
- 홀드 입력 → 탭
- 오디오 파형을 텍스트 알림으로 병기
- 야간 추적 장면을 선택형 카드로 대체하는 스토리 모드

- 모든 입력은 홀드·연타 없이 단일 입력으로 치환 가능해야 한다(15.6 '홀드 입력 → 탭'과 동일 계층).

- 커서 이동 대상은 포커스 순환으로 전부 도달 가능해야 한다.

### 18.6 조건 DSL 정의 (v4.0 신설)

18.4의 `condition` 문법을 정식화한다. 이벤트·괴이·엔딩·모듈 해금 조건은 모두 이 DSL의 단일 불리언 표현식으로 기술한다.

문법

```
expr        := or_expr
or_expr     := and_expr { "||" and_expr }
and_expr    := unary_expr { "&&" unary_expr }
unary_expr  := [ "!" ] ( comparison | "(" expr ")" )
comparison  := ref op literal | ref          (ref 단독은 불리언 필드)
op          := "==" | "!=" | ">=" | "<=" | ">" | "<"
literal     := 정수 | true | false | "문자열"
```

연산자

| 종류 | 연산자 | 비고 |
| --- | --- | --- |
| 비교 | == != >= <= > < | 정수·문자열·불리언. 문자열은 ==·!=만 허용 |
| 논리 | && \|\| ! | 단락 평가 |
| 그룹 | ( ) | 우선순위: ( ) > ! > 비교 > && > \|\| |

산술(+ - * /), 대입, 함수 호출은 지원하지 않는다. 밸런스 수식은 시뮬레이션 코어 코드가 소유하고, DSL은 상태 조회만 한다.

참조 가능 필드

| 분류 | 필드 | 타입·범위 |
| --- | --- | --- |
| 진행 | day | 정수 1~8 (1=D-7 … 7=D-1, 8=D-0) |
| 진행 | phase | 문자열: briefing / scramble / production / reality_event / confirm / overtime / backstudio / production_log / d0_screening |
| 진행 | difficulty | 문자열: rough_cut(가편집) / main_cut(본편집) / director_cut(감독판) / uncompressed(무압축) |
| 트랙 | story, footage, post, master | 정수 0~100 |
| 자원 | clientTrust, sourceIntegrity, fear, audienceResonance | 정수 0~100 |
| 자원 | budget | 정수 -1000000~7000000 |
| 자원 | revisionDebt | 정수 0~60 |
| 자원 | coffee, snack | 정수 0 이상 |
| 인물 | char.&lt;id&gt;.focus / .hp / .bond | 정수 0~100. id: heoparang, leeyounglim, leehyemi, sonmirim, player |
| 플래그 | flag.&lt;name&gt; | 불리언 또는 정수 (예: flag.source0000Seen, flag.creditLedgerPieces 0~3) |
| 도감 | codex.&lt;괴이ID&gt; | 불리언, 등록 여부. ID의 하이픈은 밑줄로 치환한다 (GH-04 → codex.GH_04) |
| 모듈 | pack.&lt;모듈ID&gt; | 불리언, 장착 여부 (PK-07 → pack.PK_07) |
| 당일 | overtimeToday | 정수 0~3, 당일 야근 인원 |
| 당일 | confirmFailStreak | 정수, 컨펌 연속 실패 횟수 |

트랙·자원 최상위 필드명은 접두어 없이 참조한다(`post >= 15`, `clientTrust < 45`). 필드명은 전역 유일을 보장한다.

평가 규칙

- 평가 시점은 이벤트 추첨 직전이며, 상태 스냅샷에 대해 1회 평가한다.
- 미설정 flag는 false(정수 플래그는 0)로 평가한다.
- 존재하지 않는 필드 참조·파싱 실패는 전체 조건을 false로 평가하고 경고 로그를 남긴다. 런은 중단하지 않는다.

### 18.7 세이브 구조 (v4.0 신설)

런 세이브와 메타 세이브를 분리한다. 런 세이브는 하루 페이즈 경계마다 자동 저장하고, 메타 세이브는 런 종료·리테이크 노트 정산·모듈 구매 시 저장한다. 로컬 저장 키는 `d7.run`, `d7.meta` 두 개다.

키 네이밍

- JSON 내부 키는 camelCase.
- 콘텐츠 ID는 원전 표기 그대로 문자열 값으로 저장한다("GH-04", "PK-07", "ED-11").
- 모든 세이브 최상위에 `schemaVersion`을 둔다.

런 세이브 예시 (`d7.run`)

```json
{
  "schemaVersion": "4.0.0",
  "seed": 20260815,
  "difficulty": "main_cut",
  "day": 4,
  "phase": "confirm",
  "state": { "...": "18.3 상태 스키마 전체" },
  "rng": {
    "scramble": 1042,
    "production": 88,
    "reality": 12,
    "backstudio": 7,
    "vfx": 331
  },
  "eventLog": ["OF_01_MORE_EMOTIONAL", "GH-01"],
  "cooldowns": {"GH-01": 2},
  "reservedChains": [{"eventId": "GH-08", "day": 5}],
  "confirmFailStreak": 1,
  "restoreUsed": 0
}
```

`rng`는 스트림별 호출 카운트다. 시드와 카운트만 있으면 18.5의 결정적 랜덤을 그대로 복원한다. `restoreUsed`는 무압축 난이도의 복원(루프) 3회 제한 검사에 쓴다.

메타 세이브 예시 (`d7.meta`)

```json
{
  "schemaVersion": "4.0.0",
  "retakeNotes": 184,
  "packsOwned": ["PK-01", "PK-03"],
  "codex": ["GH-01", "GH-04"],
  "endingsSeen": ["ED-02"],
  "bestScore": 87,
  "runsCompleted": 6,
  "stats": {"maxDayReached": 8, "totalOvertime": 11}

```

버전 마이그레이션 1줄 규칙

> 로드 시 `schemaVersion`이 현재 버전보다 낮으면 마이그레이션 함수를 버전 순서대로 체인 적용하고, 알 수 없는 키는 삭제하지 않고 보존한다.

### 18.8 이벤트 추첨 의사코드 (v4.0 신설)

하루 사이클에서 현실 이벤트(reality 스트림)와 괴이(backstudio 스트림)는 같은 추첨기를 쓴다. 순서는 풀 필터링 → 체인 예약 확인 → 가중치 → 추첨 → 쿨다운·체인 갱신이다. 이면 스튜디오는 추첨 전에 이면 조우율 판정(6장 공식)을 먼저 통과해야 한다. 현실 이벤트 20종은 전부 once(한 런 1회)이므로 쿨다운은 괴이(GH) 계열에만 적용된다.

```
function drawEvent(pool, state, rngStream):

  ## 1. 풀 필터링
  candidates = []
  for e in pool:
    if e.phase != state.phase:            continue
    if not evalCondition(e.condition):    continue   # 18.6 DSL
    if e.once and e.id in state.eventLog: continue   # once 이벤트 재등장 금지
    if state.cooldowns[e.id] > 0:         continue   # 쿨다운 중
    candidates.add(e)

  ## 2. 체인 예약 우선
  reserved = state.reservedChains.firstMatch(state.day, state.phase)
  if reserved != null:
    if reserved.eventId in candidates:               # 예약도 condition을 만족해야 발동
      return finalize(reserved.eventId)
    else:
      reserved.day += 1                              # 불만족 시 다음 날로 이월
  # 진엔딩 체인(IT-30 → GH-08 → GH-09 → … → GH-14 → GH-15)의
  # 순서 보장은 전적으로 이 예약 큐가 담당한다.

  ## 3. 가중치
  for e in candidates:
    w = e.baseWeight                                 # 기본 100
    w *= tagModifier(e, state)                       # 예: revisionDebt >= 20이면 '수정' 태그 ×1.5
    w *= repeatPenalty(e, state)                     # 최근 2일 내 동일 태그 등장 시 ×0.5
    e.weight = w

  ## 4. 추첨
  if candidates.isEmpty():
    return finalize(fillerEventFor(state.phase))     # 계열별 필러 1종, 페이즈는 비우지 않는다
  picked = weightedPick(candidates, rngStream)       # reality 또는 backstudio 전용 스트림

  ## 5. 쿨다운·중복·체인 갱신
  return finalize(picked.id)

function finalize(eventId):
  e = pool[eventId]
  state.eventLog.append(e.id)
  state.cooldowns[e.id] = e.cooldown ?? 2            # 기본 쿨다운 2일
  if e.nextInChain != null:
    state.reservedChains.add({
      eventId: e.nextInChain,
      day: state.day + (e.chainDelay ?? 1)           # 기본 다음 날 예약
    })
  return e
```

중복 규칙 요약

- `once: true` 이벤트는 런 내 1회.
- 동일 id는 쿨다운(기본 2일) 경과 후에만 재추첨된다.
- 동일 페이즈에서 이벤트는 기본 하루 1건이다. 단, 10장 운용 규칙의 조건부 1건(확정 발생 이벤트)은 예약 큐로 처리되어 일반 추첨 1건과 같은 날 겹칠 수 있다. 예약 이벤트만 있는 날은 일반 추첨을 생략한다.
- 추첨은 전용 PRNG 스트림만 소비하므로, 같은 시드·같은 선택이면 같은 이벤트가 나온다(18.5와 정합).

## 21. 최종 제작 원칙

1. 엑스컴은 콘텐츠 제작사다. 모든 시스템은 장면·원본·사람·납품을 중심으로 돌아간다.
2. 다섯 사람 중 누구도 장식 인물이 아니다. 각자만 해결할 수 있는 문제가 있다.
3. 플레이어는 천재가 아니라 연결자다.
4. 낮의 웃음은 실제 제작 언어에서 나온다.
5. 밤의 공포는 미디어와 기록의 오작동에서 나온다.
6. 야근은 강력하지만 최적해가 아니다.
7. 좋은 콘텐츠와 건강한 제작 방식은 서로 반대가 아니다.
8. 진엔딩은 귀신을 지우는 것이 아니라 출처를 되찾는 것이다.
9. 최종본은 파일 하나가 아니라, 원본·권리·크레딧·인수인계가 연결된 상태다.
10. 게임이 끝났을 때 플레이어에게 남아야 할 문장은 하나다.

모든 장면에는 만든 사람이 있다.
