# PART 1. 아트 디렉션

## 1. 비주얼 컨셉 — "1994년에 지어진 아파트의 질감"

원작이 1950년대 미국 교외의 레트로 팝 감성을 썼다면, 본작의 시대 감각은 **1990년대에 지어져 2020년대까지 살아남은 한국 아파트**다.
새것도 아니고 폐허도 아닌, **낡았지만 여전히 관리되고 있는** 공간의 질감.

### 1-1. 아트 스타일
| 요소 | 방향 |
|------|------|
| 기본 | 2D 수작업 라인 드로잉 + 플랫 셰이딩. 두꺼운 외곽선(2~3px), 손그림 떨림 유지 |
| 참조 톤 | 한국 만화 세대의 펜선 + 관공서 인쇄물의 인쇄 겹침(misregistration) 질감 |
| 텍스처 | 종이 지질(紙質) 오버레이 상시. 오래된 업무일지의 누런 기미 |
| 수집 단계 | 쿼터뷰 아이소메트릭. 벽 하프컷. 45° 고정 카메라 |
| 생존 단계 | 정면 1컷 대피소 일러스트 (누적 변화) + 텍스트 UI |
| 인물 | 흉상 컷인. 표정 3단계(정상/불안/공황) × 상태 오버레이(부상 붕대·마스크·기침) |

### 1-2. 컬러 팔레트

```
■ 회백(灰白) — 재난 색      #C9C7BF  #A8A6A0  #7C7A75
■ 콘크리트 — 공간 기본      #6E6E6A  #4A4A48  #2C2C2B
■ 형광등 — 유일한 조명      #E8E4C9  (2700K가 아닌 오래된 주광색)
─────────────────────────────────────────────────────
액센트 (희망·인간·생활):
■ 김치 빨강                 #C0392B   식량·경고·생명
■ 부르스타 파랑             #2E86AB   가스 불꽃·전력·정보
■ 콩나물 노랑               #E3B23C   생산·수확·성과
■ 재난문자 앰버             #F39C12   경보 UI 전용
```

**규칙**
- 화면의 채도는 **일차가 진행될수록 낮아진다** (1일차 100% → 21일차 62%)
- 액센트 컬러는 **화면 면적의 8% 이하**로 제한 → 회백의 무채색이 지배
- 콩나물 노랑은 **생산 라인이 작동할 때만** 등장 → 시각적 희망 신호
- 회백폐 환자가 있으면 화면 하단에 회백색 비네트

### 1-3. 대피소 누적 변화 (핵심 연출 자산)

같은 1컷 배경이 21일에 걸쳐 변한다. 플레이어의 선택이 **그림으로 축적**되어야 한다.

| 레이어 | 변화 조건 |
|--------|----------|
| 조명 | 형광등 2개 → 1개(3일차 정전) → 손전등/양초/랜턴(선택에 따라) |
| 밀폐 | 문틈에 청테이프 X자 → 실리콘 마감 → 비닐 음압실 |
| 생산 | 콩나물 시루(4일 주기로 자라는 3단계 스프라이트) / 호스 배관 / 정수 장치 / 자전거 발전기 |
| 인원 | 각자의 자리. 사망 시 **빈 담요만 남는다** (시체 묘사 없음) |
| 위생 | 쓰레기 누적 3단계 / 분리배출 이행 시 정리된 박스 |
| 침수 | 바닥 회색 물 15cm + 물자 고지대 이동 |
| 벽 | 달력 표시(작대기), 아이 낙서, 반상회 회의록 붙임 |
| 반려견 | 또리의 위치가 매일 바뀐다. 아픈 사람 옆에 가 있는다 |

> **"어제와 다른 그림"** 이 플레이어를 하루 더 붙잡는다.
> 21일차 대피소 그림은 그 회차의 요약이 되어야 하며, 스크린샷 공유 동기가 된다.

## 2. 사운드 디렉션

사운드가 본작의 **첫 번째 인상**이다. 오프닝은 그림보다 소리로 시작한다.

### 2-1. 시그니처 사운드 (5종)
| # | 소리 | 사용 |
|---|------|------|
| 1 | **위급재난문자 경보음** (삐빅-) | 오프닝. 게임 로고 이전. 유일하게 볼륨 100% |
| 2 | **민방위 사이렌** (상승-하강) | 수집 단계 배경. 마지막 10초에 피치 +2세미톤 |
| 3 | **단지 안내방송** (잡음 섞인 노년 남성) | "지금은 실제 상황입니다" — 타이틀 트리거 |
| 4 | **형광등 안정기 웅웅거림** | 생존 단계 앰비언스 베드. 60Hz 험 + 랜덤 깜빡임 |
| 5 | **부탄가스 점화음 + 물 끓는 소리** | 조리 액션. **유일하게 따뜻한 소리** |

### 2-2. 앰비언스 레이어
```
[베이스]   지하 공간 룸톤 (저역 -12dB 셸빙)
[레이어 1] 형광등 험 (조명 상태에 연동, 소등 시 제거 → 정적이 무섭다)
[레이어 2] 물방울 (배수구. 회니 역류 임박 시 간격 짧아짐)
[레이어 3] 환기구 바람 (개방 시 화이트노이즈 + 미세한 모래 소리)
[레이어 4] 위층 소리 (10일차+ 발소리. 규칙적 → 불규칙적으로 변화)
[레이어 5] 인물 (기침·아이 뒤척임·또리 발톱 소리·노인 숨소리)
```

### 2-3. 음악
| 구간 | 편성 | 의도 |
|------|------|------|
| 오프닝~수집 | 음악 없음. 사이렌과 발소리만 | 정보 과부하 방지 |
| 생존 1~7일차 | 리코더 + 프리페어드 피아노, 4마디 루프 | 서툴고 소박한 희망 |
| 8~15일차 | 위 + 저역 신스 드론 추가 | 압박의 축적 |
| 16일차+ | 루프 해체. 단음만 남는다 | 고갈의 청각화 |
| 반상회 | 리듬 없는 하모니움. 발언마다 코드 1개 | 절차의 냉정함 |
| 조리 성공 | 4초 짧은 장조 모티프 | **유일한 보상 음악** |
| 엔딩 | 엔딩 계열별 3종. 「우리 단지」만 앙상블(사람 수만큼 악기가 늘어난다) | 생존자 수가 편성이 된다 |

> **음악 설계의 핵심:** 「우리 단지」 엔딩 음악은 **생존자 1명당 악기 1개**로 편성된다.
> 4명이면 4중주, 12명이면 합주. 플레이어는 자기 회차의 결과를 **듣는다.**

## 3. UI 디렉션

### 3-1. UI 컨셉 — "관리사무소 서식"

모든 UI는 아파트에서 실제로 볼 수 있는 인쇄물의 형태를 빌린다.

| 화면 | 차용 서식 |
|------|----------|
| 일지 | **관리사무소 업무일지** — 볼펜 필기체, 인쇄된 표 칸 |
| 자원 현황 | **관리비 부과 내역서** — 항목별 우측 정렬 숫자, 합계란 |
| 배급 설정 | **당번표 / 검침표** — 인원 × 날짜 격자에 체크 |
| 반상회 | **입주자대표회의 회의록** — 안건 번호, 참석자 서명란, 표결 집계 |
| 단톡방 | 실제 메신저 UI 모사 (색상·말풍선 형태는 오리지널로 디자인) |
| 탐색 지시 | **작업지시서** — 담당자·목적지·장비 3칸 |
| 엔딩 | **공고문** — 아파트 게시판에 붙은 A4, 압정 4개 |
| 도감 | **세대 관리 카드** — 색인 탭이 달린 인덱스 카드 |

### 3-2. 접근성
| 항목 | 대응 |
|------|------|
| 색약 | 회백/액센트 구분을 채도만으로 의존하지 않음. 모든 상태에 아이콘 + 텍스트 병기 |
| 폰트 | 본문 최소 16px 상당. 시스템 폰트 크기 3단 (100/125/150%) |
| 청각 | 모든 시그니처 사운드에 자막 + 화면 테두리 시각 신호 (재난문자 = 앰버 플래시) |
| 시간 압박 | 「수집 시간 연장」 접근성 옵션 (150/180/무제한) — 실적 획득에 영향 없음 |
| 광민감성 | 형광등 깜빡임·재난문자 플래시 비활성 옵션 |
| 입력 | 마우스 전용 / 키보드 전용 / 게임패드 전용 각각 완전 조작 가능 |
| 언어 | 한국어(원본) · 영어 · 일본어 · 중국어(번체/간체) · 스페인어 · 폴란드어 |

### 3-3. 화면 흐름
```
타이틀 → 모드 선택 → 난이도 → [오프닝] → 수집(120초) → 결산
   → 생존 루프 (일차 반복: 갱신 → 배급 → 액션 → 이벤트 → 일지)
   → 엔딩 → 결과 요약 → 도감 갱신 → 타이틀
```
- **1회차 흐름 목표: 어떤 메뉴도 3클릭 이상 들어가지 않는다.**
- 생존 루프의 1일 진행은 **최소 4클릭 / 최대 12클릭**으로 유지 (25~40분 회차 유지)

# PART 2. 기술

## 4. 기술 스택

| 영역 | 선택 | 근거 |
|------|------|------|
| 엔진 | **Godot 4.x (C#)** | 2D 우선 엔진, 로열티 없음, 소규모 팀 이터레이션 속도. Steam·모바일·Switch 대응 |
| 대안 검토 | Unity 6 (2D URP) | 콘솔 인증 경험/에셋스토어 이점은 있으나 라이선스 리스크와 2D 오버헤드로 후순위 |
| 데이터 | 외부 JSON (`items/events/characters/balance`) + 스키마 검증 | 밸런싱을 코드 배포 없이 반복 (09 문서 6장) |
| 로컬라이즈 | CSV 기반 키-값 + 런타임 폰트 폴백 | 이벤트 텍스트 156종 × 6언어 = 936 스트링 |
| 세이브 | JSON + 체크섬. 하드코어는 사망 시 삭제 | 치트 방지는 최소한만 (싱글 게임) |
| 난수 | 시드 고정 xorshift128+. 시드 문자열 공유 기능 | 챌린지·스트리머 재현성 |
| 분석 | 익명 텔레메트리 (옵트인): 사망 일차·사인·엔딩·회차 | 09 문서 튜닝 가드레일 12개 지표 자동 수집 |
| CI | GitHub Actions — 데이터 스키마 검증 + 시뮬레이터 회귀 테스트 | 밸런스 붕괴 조기 감지 |

## 5. 밸런스 시뮬레이터 (개발 인프라)

**게임 없이 밸런스를 검증하는 헤드리스 시뮬레이터를 먼저 만든다.**

```
tools/sim/
  ├── run.ts            # 10,000판 몬테카를로 실행
  ├── policies/         # AI 배급 정책 (균등 / 가족우대 / 아동우선 / 최적)
  ├── report.ts         # 09 문서 12개 지표 자동 산출
  └── regress.json      # 기준선 → CI에서 ±10% 벗어나면 실패
```

| 검증 항목 | 자동 판정 |
|----------|----------|
| 균등 배급 일변도 승률 | 25~45% (100%면 리스크 1 발현 → 총량 하향) |
| 신뢰도 붕괴 실패 비중 | 30~40% |
| 물 고갈 실패 비중 | 20~30% |
| 21일 도달률 (노멀) | 30~45% |
| 아이템별 픽률 편차 | 상위 5종이 60% 초과하면 스폰율 재조정 |

> **이 시뮬레이터가 본 프로젝트의 최대 리스크 헤지다.**
> 이벤트 52종 × 아이템 78종 × 이웃 14종의 조합은 사람의 플레이테스트만으로 검증할 수 없다.
> 프로토타입 착수 전에 시뮬레이터를 먼저 만든다.

## 11. 마케팅 전략 3축

### 축 1 — 사운드 훅 (SNS)
**첫 3초에 재난문자 경보음.** 릴스/쇼츠에서 스크롤을 멈추게 하는 것은 그림이 아니라 이 소리다.
- 15초 클립 포맷: 경보음 → 120초 카운트다운 → "무엇을 챙기시겠습니까?" → 선택지 3개 → 댓글 유도
- 예상 확산 지점: "라면 챙길 사람 vs 도끼 챙길 사람" 논쟁

### 축 2 — 스트리머 모드 (실황)
반상회 표결을 시청자 투표로 위임하는 기능은 **국내 인디의 최대 유입 채널에 직접 붙는 설계**다.
- 사전 접촉 100명 → 데모 시드 배포 → 「같은 집으로 도전」 챌린지
- 회차 25~40분 = 실황 1편 분량으로 최적

### 축 3 — 공감 마케팅 (커뮤니티)
「층간소음(지하 3층에서)」, 「관리비 고지서」, 「확인했습니다 👍」 같은 이벤트 스크린샷은 그 자체로 커뮤니티 콘텐츠다.
- 아파트 거주 경험 기반 밈 → 게임 외부에서 먼저 화제화
- 출시 전 6주간 「이번 주 반상회 안건」 SNS 시리즈 (실제 게임 안건 14종 순차 공개)

## 13. 정리 — 이 기획의 한 줄

> 원작 *60 Seconds!* 는 **"가족을 지하로 데려가는 게임"** 이다.
> 『실제 상황입니다』 는 **"지하에서 이웃과 함께 사는 게임"** 이다.
>
> 60초가 120초로 늘어난 만큼, 게임은 **혼자 살아남는 이야기에서 함께 살아남는 이야기로** 확장됐다.
> 그리고 함께 사는 일이 굶는 것보다 어렵다는 것이, 이 기획의 결론이다.
