### 0.3 GDD 파라미터와 본 명세 필드의 대응 규칙

GDD 19.5.1의 파라미터는 자연어 항목명이다. 본 명세는 아래 3가지 방식으로만 이를 필드화하며, **항목 자체를 늘리지 않는다**.

| 방식 | 예 | 판정 |
|---|---|---|
| 1:1 치환 | "괴이 ID" → `ghost_id: string` | 변경 아님 |

| 공통 페이로드로 승격 | "일차" → 공통 `day` | 변경 아님(전 이벤트 공통이므로 중복 제거) |

## 1. 공통 규약

### 1.1 이벤트 봉투(envelope)

전송 단위는 봉투 1건이다. 봉투는 **공통 페이로드 6필드 + 이벤트 식별 2필드 + `params` 객체**로 고정한다.

```json
{
  "schema_version": "1.0.0",
  "run_id": "9f2c1b7e-4a3d-4c88-9e51-0b7d2a6f3c14",
  "seed": "2847193056",
  "difficulty": "main_cut",
  "day": 3,
  "client_ts": "2026-08-16T14:22:07.415Z",
  "event": "confirm_result",
  "event_seq": 47,
  "params": { }
}
```

### 1.2 공통 페이로드 6필드

| 필드 | 타입 | 필수 | 범위·형식 | 정의 | 근거 |
|---|---|---|---|---|---|
| `schema_version` | string | Y | SemVer `MAJOR.MINOR.PATCH` | 본 명세의 버전. 최초 구현은 `"1.0.0"` | 콘텐츠 스키마 정의서 1.1과 동일 규약 |
| `run_id` | string | Y | UUID v4 소문자 하이픈 표기 | 런 단위 익명 식별자. 3.2 참조 | GDD 19.5 서두, 개발 7.6 3) |
| `seed` | string | Y | uint32 10진 문자열(`"0"`~`"4294967295"`) | 해당 런의 마스터 시드. 시드 고정 리플레이 대조용 | GDD 18.5, 19.5.3 |
| `difficulty` | string | Y | `rough_cut` \| `main_cut` \| `director_cut` \| `uncompressed` | 난이도. GDD 18.6 DSL 값과 동일 문자열 | GDD 6.4, 18.6 |
| `day` | integer | Y | 0~8 | 게임 내 일차. 1=D-7 … 7=D-1, 8=D-0. **0은 런 시작 전(타이틀·난이도 선택 구간)** | GDD 18.6 `day` 필드 |
| `client_ts` | string | Y | ISO 8601 UTC, 밀리초 3자리 (`Z` 접미) | 클라이언트 발화 시각. 로컬 시간대·오프셋 정보는 싣지 않는다 | 3.1 금지 필드 |

### 1.3 이벤트 식별 2필드

| 필드 | 타입 | 필수 | 정의 |
|---|---|---|---|
| `event` | string | Y | 이벤트명 15종 중 하나(snake_case) |
| `event_seq` | integer | Y | 해당 `run_id` 내 발화 순번. 1부터 시작하는 단조 증가. 결측 검출과 `run_abandon`의 직전 이벤트 지시에 사용 |

`event_seq`는 GDD 19.5.1 `run_abandon` 파라미터의 "직전 이벤트 ID"를 구현하기 위한 필수 부속 필드이며, 신규 수집 항목이 아니다.

### 1.4 타입 표기 규약

| 표기 | 뜻 |
|---|---|
| `integer` | 부호 있는 정수. JSON number로 직렬화하되 소수부를 갖지 않는다 |
| `number` | 실수. 소수 둘째 자리까지 유효(반올림, half-up). 판정 확률·점수에 사용 |
| `string` | UTF-8 문자열. 자유 입력 텍스트는 어떤 필드에도 허용하지 않는다(3.1) |
| `boolean` | true/false |
| `T[]` | T의 배열. 순서 무의미 시 사전순 정렬로 직렬화 |
| `T \| null` | 값 부재를 null로 명시. 필드 자체의 생략은 금지 |

`params`의 모든 필드는 **필수**다. 값이 없는 상황은 `null` 또는 빈 배열 `[]`로 표현하며, 필드를 빼면 스키마 위반(결측)으로 집계한다.

## 2. 개인정보 원칙 (GDD 20장 · 개발 7.6 3)

> 본 장 위반은 부속서 D AC-BAN-10에 따라 **3급(중대 하자)** 이다. 해당 빌드는 외부 배포가 금지되고, 하자보수 기간과 무관한 무상 수정 의무가 발생한다.

### 2.1 금지 필드 — 어떤 이벤트에도 싣지 않는다

| 분류 | 금지 대상 | 비고 |
|---|---|---|
| 인적 식별 | 실명, 닉네임, 계정 ID, 이메일, 전화번호 | GDD 20.1 |
| 표시명 | GDD 20.3 `displayNameMode.real` / `.fictional` 값 | 인물 참조는 `heoparang` 등 **characterId 원형만** 사용. characterId는 게임 콘텐츠 식별자이며 수집 대상(플레이어)의 식별 정보가 아니다 |
| 네트워크 | IP 원문, 프록시 헤더 원문 | 서버는 라우팅 목적의 메모리 내 사용만 허용하고 **저장하지 않는다** |
| 기기 | 기기 식별자, 광고 ID, User-Agent 원문, 화면 해상도, 설치 폰트, GPU 문자열 | 조합 시 핑거프린트가 성립하므로 개별 항목도 금지 |
| 위치·시간대 | 지리 위치, 로컬 시간대, UTC 오프셋 | `client_ts`는 UTC 고정 |
| 자유 텍스트 | 플레이어 입력 문자열 일체 | 본 게임은 자유 입력 UI를 두지 않으므로 원천적으로 발생하지 않아야 한다 |
| 런 간 연결 키 | 기기별 영속 ID, 세션 쿠키, 로그인 토큰 | 2.2 참조 |

서버 수신 시각을 남기는 경우 **분(minute) 단위로 절사**하여 `client_ts`와의 조합으로 개인을 특정할 수 없게 한다.

### 2.2 `run_id` 규정

1) 생성: 런 시작(난이도 확정, `run_start` 발화) 직전에 `crypto.randomUUID()`(UUID v4)로 생성한다. 시드·시각·기기 정보에서 파생시키지 않는다.
2) 수명: 해당 런 종료(`run_end` 또는 `run_abandon`) 시 폐기한다.
3) **메타 세이브(`d7.meta`)에 저장 금지.** GDD 18.7의 메타 세이브는 런을 넘어 존속하므로, 여기에 `run_id`나 그 이력을 남기면 익명성이 런 간 연결로 무너진다.
4) 런 세이브(`d7.run`)에는 저장한다. 21:57 전환 중 강제 종료 후 재시작(GDD 19.5.2 세이브 항목)에도 같은 런의 이벤트가 같은 `run_id`로 이어져야 하기 때문이다.
5) 플레이어 단위 지표(재루프 전환율)는 `run_id` 연결이 아니라 `run_start.run_count` 값의 분포로 산출한다(4.2 참조).

### 2.3 로컬 저장 규정

| 항목 | 규정 |
|---|---|
| 저장 키 | `d7.telemetry.queue` — GDD 18.7의 `d7.run` · `d7.meta`와 **분리**한다. 세이브 무결성 검수(자동 테스트 5번)의 상태 해시 대상에 텔레메트리 큐가 섞이지 않게 한다 |
| 자료 구조 | 링버퍼. 최대 500건. 초과 시 가장 오래된 건부터 폐기하고 폐기 건수를 `dropped_count`로 로컬 카운트(전송하지 않음, 8장 데이터 품질 뷰에서 QA가 육안 확인) |
| 직렬화 | 봉투 배열의 JSON 문자열 1개 |
| 잔류 | 전송 성공 건은 즉시 큐에서 제거한다. 미전송 건은 다음 실행 시 재시도 대상이 된다 |
| 수집 중단 시 | 큐를 비우고 발화를 정지한다(2.5) |

### 2.4 전송 규정

| 항목 | 규정 | 근거 |
|---|---|---|
| 엔드포인트 | 발주자가 지정한 **단일** 수집 엔드포인트. 개발사 자체 서버로의 이중 수집 금지 | 개발 7.6 3) |
| 전송 시점 | ① 페이즈 경계(GDD 18.6 `phase` 전이 시) ② 30초 주기 — 둘 중 먼저 오는 시점에 배치 전송 | 페이즈 경계 저장(GDD 18.7)과 사이클 일치 |
| 배치 크기 | 요청당 최대 50건 | |
| 즉시 전송 예외 | `run_abandon`은 `navigator.sendBeacon()`으로 단건 즉시 전송. 페이지 언로드 중 유실을 막기 위함 | GDD 19.5.1 #11 |
| 실패 처리 | 지수 백오프 재시도 3회(1s → 2s → 4s), 이후 큐 잔류. **게임 진행을 막지 않는다** | 개발 7.6 4) |
| 비동기 | 전송은 게임 루프와 분리된 비동기 큐에서 수행한다. 전송 대기가 씬 전환·판정을 블로킹해서는 안 된다 | 개발 7.6 4) |
| 순서 | 봉투는 `event_seq` 순으로 전송한다. 서버는 순서 역전을 허용하되 `event_seq` 기준으로 재정렬한다 | |

### 2.5 고지와 옵트아웃

1) 최초 실행 시 수집 고지를 표시한다. 개발 7.5 3)이 요구하는 광과민성 고지 화면에 통합하여 화면을 추가하지 않는다.
2) 설정 메뉴에 수집 중단 토글을 둔다(옵트아웃). 중단 선택 시 로컬 큐를 비우고 이후 발화를 정지한다.
3) 수집 중단 상태는 메타 세이브의 설정 항목으로 보존하되, 그 값 자체를 전송하지 않는다.
4) 고지 문구·동의 방식의 최종 확정은 발주자 소관이다(개발 7.6 3, 체크리스트 CP-E06). 본 명세는 구현 구조만 규정한다.

### 2.6 보관

1) 원자료는 발주자가 지정한 위치에만 보관한다.
2) 게이트 검수 완료 후 6개월이 지난 원자료는 파기하고, 집계 결과(4장 지표)만 보존할 것을 권고한다.
3) 개인정보 관련 법령 적합성 확인은 발주자 소관이다(개발 3장 인도물 유의사항 3항, 체크리스트 CP-E05).

| 발화 시점 | 런 미완료 상태의 세션 종료 — ① `visibilitychange`로 `hidden` 전이 후 복귀 없이 언로드 ② `beforeunload` ③ 타이틀 화면으로의 명시적 복귀 |
| 발화 횟수 | `run_id`당 최대 1회. 중복 방지 플래그를 런 세이브에 둔다 |
| 전송 | `navigator.sendBeacon()` 단건 즉시 전송(2.4) |
| 보려는 지표 | 일차별 이탈 지점, 이탈 직전 맥락 |
| 집계 방식 | `day` 분포, `phase` 분포, `day × phase` 히트맵 |
| 샘플링 | 전수(100%) |

```json
{
  "phase":          "string  // GDD 18.6 phase 열거값 9종 중 하나",
  "last_event":     "string  // 직전 발화 이벤트명",
  "last_event_seq": "integer // 직전 발화의 event_seq"
}
```

- `last_event` + `last_event_seq`는 GDD 19.5.1 "직전 이벤트 ID" 1항목의 구성 상세다.
- 세이브 후 재개(이어서 편집)로 같은 런이 계속되면 `run_abandon`은 **취소되지 않는다**. 이미 발화한 건은 유지하고, 재개 이후 이벤트는 같은 `run_id`로 계속 발화한다. 집계에서는 이후 `run_end`가 있는 `run_id`를 이탈에서 제외한다(4.5).

### 3.12 `true_end_step`

| 항목 | 내용 |
|---|---|
| 발화 시점 | 진엔딩 체인 단계(1.5 표 `TE-01`~`TE-09`)의 달성 조건이 성립한 즉시 |
| 발화 횟수 | 각 단계당 런 1회(재조우로 재시도해도 최초 성립 시 1회만) |
| 보려는 지표 | 진엔딩 체인 진입률, 단계별 감쇠 |
| 집계 방식 | 단계별 퍼널(`TE-01` 기준 상대 도달률) |
| 샘플링 | 전수(100%) |

```json
{
  "step_id":         "string // TE-01 ~ TE-09",
  "ledger_pieces":   "integer // 발화 시점 크레딧 장부 조각 수. 0~3",
  "rights_list_pct": "number  // 발화 시점 원본·권리 목록 진행률(%). 0.00~100.00"
}
```

- `step_id`는 GDD 19.5.1 "단계 ID(IT-30~ED-11)"의 열거화다. 순서 위반 진입은 GDD 19.5.2에서 0건이어야 하므로, 서버는 `event_seq` 기준 단계 순서 역전을 품질 위반으로 집계한다(8장 V8).

### 3.13 `run_end`

| 항목 | 내용 |
|---|---|
| 발화 시점 | 엔딩 확정 후 `Ending` 씬 진입 시, `RetakeNote` 정산 화면 **진입 전** |
| 발화 횟수 | 런당 1회 |
| 공통 `day` | 엔딩 확정 시점 일차(즉시 실패형은 8 미만일 수 있다) |
| 보려는 지표 | 엔딩 분포(ED-01~12), 점수·티어 분포 |
| 집계 방식 | 엔딩별 카운트·구성비, `delivery_score` 히스토그램(5점 버킷), 티어 분포 |
| 샘플링 | 전수(100%) |

```json
{
  "ending_id":      "string  // ED-01 ~ ED-12",
  "tier":           "string  // instant_fail | base_fail | d0_tech_fail | bad_source | success | special | true",
  "delivery_score": "number  // D-0 납품 점수. 0.00~100.00. 게이트 미도달 실패 시 산출값 그대로",
  "retake_notes":   "integer // 이번 런에서 획득한 리테이크 노트 총량(난이도 배율 적용 후)"
}
```

- `delivery_score`는 GDD 5장 납품 점수 공식의 최종값이며 **소수 2자리**로 싣는다. 개발 4.3.2 2항의 균형 플레이 92.44점 ±0.01 재현 판정이 이 정밀도를 요구한다.

### 3.14 `module_purchase`

| 항목 | 내용 |
|---|---|
| 발화 시점 | `RetakeNote` 화면에서 모듈 구매 확정 직후, 잔액 차감 반영 후 |
| 발화 횟수 | 구매 1건당 1회 |
| 공통 `day` | `0`(런 종료 후 메타 구간) |
| 보려는 지표 | 모듈 인기 순위, 재화 경제 검산 |
| 집계 방식 | 모듈별 구매 카운트·구매 순번 중앙값, 잔액 곡선 |
| 샘플링 | 전수(100%) |

```json
{
  "module_id":     "string  // PK-01 ~ PK-16",
  "cost":          "integer // 구매 비용(리테이크 노트)",
  "balance_after": "integer // 구매 후 잔액. 0 이상",
  "run_count":     "integer // 구매 시점의 누적 런 회차"
}
```

- `run_count`가 `run_start`와 중복되는 것은 GDD 19.5.1 표가 두 이벤트 모두에 "회차 수"를 배정했기 때문이다. 메타 구간 발화는 `run_id`가 직전 런의 것이므로 회차를 다시 실어야 GDD 13.5 이코노미 검산(10~12런 완주 곡선)의 대조가 성립한다.

### 3.15 `accessibility_toggle`

| 항목 | 내용 |
|---|---|
| 발화 시점 | 접근성 옵션 변경 확정 직후. 메뉴·인게임 일시정지 메뉴 양쪽 모두 |
| 발화 횟수 | 변경 1회당 1회 |
| 보려는 지표 | 접근성 옵션 사용률, 광과민성 저감 모드 채택률 |
| 집계 방식 | 옵션별 접촉률·유지율(4.8), `context` 구성비 |
| 샘플링 | 전수(100%) |
| 대응 AC | AC-ACC-11(플레이 중 10종 토글 조작과 로그 대조) |

```json
{
  "option_id": "string  // ACC-01 ~ ACC-10",
  "enabled":   "boolean // 변경 후 상태",
```

- `level`은 GDD 19.5.1 "on/off" 항목의 구성 상세다. ACC-04만 3단계 값을 가지므로 boolean 하나로는 표현되지 않는다.

## 4. 지표 산출식

### 4.0 공통 규약

| 항목 | 규정 |
|---|---|
| 집계 단위 | 별도 명시가 없으면 **고유 `run_id` 수**를 센다. 같은 런에서 같은 이벤트가 여러 번 발화해도 1로 센다 |
| 집계 창 | 게이트 판정용 집계는 해당 게이트 제출 빌드 버전으로 한정한다. 빌드 버전이 섞인 집계는 판정에 쓰지 않는다 |
| 표본 하한 | 게이트 1은 외부 플레이테스터 15명 이상, 게이트 3은 30명 이상. 미달 시 산출값을 판정 데이터로 사용하지 않는다(개발 4.3.4 1항) |
| 반올림 | 백분율은 소수 첫째 자리까지 half-up |
| 결측 처리 | 스키마 위반 봉투는 분자·분모 모두에서 제외하고, 제외 건수를 V8에 표시한다 |

### 4.1 FTUE 완주율 (튜토리얼 완료율)

**기준**: 92% 이상 (개발 4.3.3 1항, GDD 14.1 퍼널 1)

```
분모 = count(distinct run_id | run_start.params.run_count == 1)
분자 = count(distinct run_id | run_start.params.run_count == 1 AND day_end(day == 1) 발화)
FTUE 완주율 = 분자 ÷ 분모 × 100
```

- 관측점 근거: GDD 14.2 온보딩 단계 11이 제작일보이고 단계 12(D-7 복원 안내)는 제작일보 확정 직후 자동 전개되는 화면이므로, `day_end(day == 1)`가 12단계 통과의 유일한 관측점이다.
- **한계 고지**: 텔레메트리 15종으로는 온보딩 1~11단계 각각의 이탈 지점을 분해할 수 없다. 단계별 분해가 필요하면 발주서 11장 변경 절차로 이벤트·파라미터 확장을 승인해야 한다(체크리스트 CP-X04). 미승인 상태에서는 QA 관찰 기록으로 보완한다.

### 4.2 재루프 전환율

**기준**: 55% 이상 (개발 4.3.3 1항, GDD 14.1 퍼널 6)

```
분모 = count(distinct run_id | run_start.params.run_count == 1
                              AND (run_end 발화 OR run_abandon 발화))
분자 = count(distinct run_id | run_start.params.run_count >= 2)
재루프 전환율 = 분자 ÷ 분모 × 100
```

- 산출 방식 근거: 2.2 3항에 따라 `run_id`를 런 간 연결하지 않으므로 플레이어 단위 추적이 불가능하다. 대신 메타 세이브 누적값 `run_count`의 분포로 근사한다. 게이트 판정 표본(15~30명)은 배포 단위가 통제되므로 이 근사가 성립한다.
- 분모에서 종료 관측(`run_end` 또는 `run_abandon`)을 요구하는 이유는, 첫 런이 끝나지도 않은 세션을 전환 실패로 세지 않기 위함이다.
- 조건부 통과 경계값(개발 4.3.3 5항): 기준치의 90%인 **49.5%**.

### 4.3 야근 선택률

**기준**: GDD 19.5.1 고정 정의 — "overtime_choice에서 인원 1 이상 비율"

```
분모 = count(overtime_choice 전건)
분자 = count(overtime_choice | params.overtime_count >= 1)
야근 선택률 = 분자 ÷ 분모 × 100
```

- 집계 단위가 **이벤트 건수**(런 단위가 아님)임에 유의한다. GDD 정의가 그러하다.
- 일차별: `day`로 그룹핑하여 같은 식을 적용한다.
- 인원별 분해(0/1/2/3명)는 `overtime_count` 분포로 병기한다(GDD 21장 원칙 6 검증).

### 4.4 컨펌 실패율

**기준**: GDD 19.5.1 고정 정의 — "confirm_result 실패 비율(일차별)"

```
분모(일차 d) = count(confirm_result | day == d)
분자(일차 d) = count(confirm_result | day == d AND params.success == false)
컨펌 실패율(d) = 분자 ÷ 분모 × 100
```

- 전체 실패율은 일차 구분 없이 같은 식으로 산출하되, **게이트 판정에 쓰는 정본은 일차별 값**이다.
- 교차 검증: `effective_rate`의 산술평균과 `1 − 실패율`의 차이가 ±2%p 이내여야 한다(GDD 19.5.3 #2 통과 기준과 동일 허용 오차).
- '컨펌 공포' 발생률 = `count(confirm_result | fail_streak >= 2)` ÷ `count(confirm_result 전건)`.

### 4.5 일차별 이탈

**기준**: GDD 19.5.1 고정 정의 — "run_abandon의 일차 분포"

```
[정본 — 구성비]
분모 = count(distinct run_id | run_abandon 발화 AND run_end 미발화)
분자(일차 d) = count(distinct run_id | run_abandon(day == d) AND run_end 미발화)
일차별 이탈 구성비(d) = 분자 ÷ 분모 × 100

[보조 — 이탈 위험도, 대시보드 전용]
진입 런 수(d) = (d == 1) ? count(run_start) : count(day_end | day == d-1)
이탈 위험도(d) = count(distinct run_id | run_abandon(day == d) AND run_end 미발화) ÷ 진입 런 수(d) × 100
```

- `run_end` 미발화 조건: 3.11 단서에 따라 세션을 끊었다가 다시 이어 완주한 런은 이탈로 세지 않는다.
- 정본은 구성비다. 위험도는 일차별 난이도 진단용 보조 지표이며 게이트 판정에 쓰지 않는다.
- 페이즈 분해: `day × phase` 교차표로 병기한다(GDD 19.5.1 #11 '이탈 직전 맥락').

### 4.6 진엔딩 체인 진입률

**기준**: GDD 19.5.1 고정 정의 — "run_start 대비 true_end_step(IT-30) 발화 비율"

```
분모 = count(distinct run_id | run_start 발화)
분자 = count(distinct run_id | true_end_step(step_id == "TE-01") 발화)
진엔딩 체인 진입률 = 분자 ÷ 분모 × 100
```

- 단계별 감쇠(퍼널): 각 단계 `TE-0k`에 대해 `count(distinct run_id | step_id == TE-0k) ÷ 분모 × 100`을 산출하고, 직전 단계 대비 잔존율도 병기한다.
- `TE-01`이 GDD 11.4의 IT-30 노드다.

### 4.7 엔딩 분포

```
분모 = count(run_end 전건)
분자(엔딩 e) = count(run_end | params.ending_id == e)
엔딩 구성비(e) = 분자 ÷ 분모 × 100    // e ∈ {ED-01 … ED-12}
```

- 티어 분포도 같은 분모로 산출한다(`tier` 7종).
- 난이도별 교차: `difficulty`로 그룹핑하여 GDD 9.5.4의 목표 승률(가편집 75% / 본편집 45% / 감독판 25%)과 대조한다. 승률 = `count(run_end | tier ∈ {success, special, true})` ÷ `count(run_end)`.

### 4.8 접근성 옵션 사용률

옵션 10종 각각에 대해 2개 지표를 산출한다.

```
[접촉률 — 런 중 1회 이상 ON]
분모 = count(distinct run_id | run_start 발화)
분자(옵션 o) = count(distinct run_id | accessibility_toggle(option_id == o AND enabled == true) 발화)
접촉률(o) = 분자 ÷ 분모 × 100

[유지율 — 런 종료 시점 ON]
분모 = count(distinct run_id | run_end 발화)
분자(옵션 o) = count(distinct run_id | run_end 발화 AND
                     해당 run_id에서 option_id == o 의 최종 enabled == true)
유지율(o) = 분자 ÷ 분모 × 100
```

- 최종 상태 판정: 같은 `run_id`·같은 `option_id`의 `accessibility_toggle` 중 `event_seq` 최대값의 `enabled`를 취한다.
- **광과민성 저감 모드 채택률**(GDD 19.5.1 #15 '보려는 것')은 `ACC-01` 플래시 감소의 **유지율**로 정의한다. 켰다 끈 사용자를 채택으로 세지 않기 위함이다.
- ACC-04는 `level` 1/2/3 각각의 유지 구성비를 별도 병기한다.
- 주의: 기본값 ON으로 출시되는 옵션이 있으면 `accessibility_toggle`이 발화하지 않아 사용률이 0으로 관측된다. **접근성 옵션 10종의 초기값은 전부 OFF로 출시**하고, 최초 실행 고지 화면(2.5)에서 안내한다.

### 4.9 게이트 1 보조 지표

개발 4.3.1이 요구하는 텔레메트리 실측 2종이다.

```
[첫 21:57 도달률 — 기준 85% 이상]
분모 = count(distinct run_id | run_start.params.run_count == 1)
분자 = count(distinct run_id | run_start.params.run_count == 1 AND night_encounter(day == 1) 발화)
첫 21:57 도달률 = 분자 ÷ 분모 × 100

[15분 수직절단 완주율 — 기준 80% 이상]
분모 = count(distinct run_id | run_start 발화)          // 회차·난이도 무관
분자 = count(distinct run_id | day_end(day == 1) 발화)
15분 수직절단 완주율 = 분자 ÷ 분모 × 100
```

- 첫 21:57 도달률의 관측점이 `night_encounter`인 근거는 3.8 단서와 같다. 미조우 시에도 발화하므로 도달 자체를 셀 수 있다.
- 15분 완주율과 FTUE 완주율(4.1)은 관측점이 동일(`day_end(day == 1)`)하고 **분모만 다르다**. 전자는 전 런, 후자는 첫 런이다. 혼동을 막기 위해 대시보드에서 두 지표를 같은 카드에 병렬 배치한다.

## 7. 수용 기준 (제안)

> 부속서 D-1.0 5항이 유보한 텔레메트리 검수 절을 채우기 위한 AC 초안이다. 발주자 승인 후 부속서 D에 편입한다. 판정 시점은 별도 표기가 없으면 게이트 3(개발 4.3.3 4항)이며, 최종 검수에서 재확인한다.

- [ ] AC-TLM-01: 이벤트 15종이 본 명세 3장의 발화 시점에서 각각 발화한다. 시드 고정 1런 리플레이의 로그에 15종 전부가 나타나고, 정의되지 않은 `event` 값이 0건이다. (게이트 1: 15종 발화 기반 동작, 게이트 3: 전수 판정)
- [ ] AC-TLM-02: 전 봉투가 공통 페이로드 6필드 + `event` + `event_seq` + `params`의 구조를 갖추고, 필드 누락·타입 불일치가 0건이다.
- [ ] AC-TLM-03: `params`의 전 필드가 3장 스키마와 일치하며, 값 부재는 필드 생략이 아니라 `null`/`[]`로 표현되어 있다.
- [ ] AC-TLM-04: `run_id`가 UUID v4이며, 같은 기기에서 연속 3런을 수행할 때 3개 값이 전부 다르고, 메타 세이브(`d7.meta`)에 `run_id` 또는 그 이력이 저장되어 있지 않다. (2.2)
- [ ] AC-TLM-05: 금지 필드(2.1) 검출이 0건이다. 판정: 1런 분량 전송 페이로드 전문을 덤프하여 금지 항목 문자열·패턴을 검색하고, 인물 참조가 characterId 원형만으로 되어 있음을 확인한다. — **위반 시 3급**(AC-BAN-10 연동)
