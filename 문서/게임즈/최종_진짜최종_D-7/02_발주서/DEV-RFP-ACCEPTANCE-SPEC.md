## D-1. 화면·기능별 수용 기준

본 절은 《최종_진짜최종: D-7》 게임 흐름 11개 단위의 화면·기능 수용 기준(AC)이다. 발주자 검수 시 각 AC는 제3자가 예/아니오로 판정한다.

### D-1.0 공통 적용 원칙

1. 근거 표기: 각 AC 말미 괄호가 검수 근거다. (GDD n.n) = 기획 정본 `문서/게임즈/최종_진짜최종_D-7/01_기획서/FINAL-FINAL-D7-GDD.md` v4.0 해당 절, (MVP) = 발주자 제공 동작 레퍼런스 `문서/게임즈/최종_진짜최종_D-7/04_MVP프로토타입/index.html`, (RFP n.n) = 발주서 본문 해당 절.
2. 수치 충돌 시 GDD가 정본이며, GDD 내부 충돌은 5~8장 수치를 정본으로 한다(GDD 0.3, RFP 1.7).
3. 'MVP 단순화' 표기가 붙은 항목은 MVP가 축약 구현한 부분으로, 본 개발은 병기된 GDD 기준을 따른다. 표기 없는 (MVP) 인용은 MVP 동작을 실행 가능한 명세로 채택한 것이다.
4. [Phase 0 확정] 표기 항목은 RFP 6.1 2)항에 따라 Phase 0 질의응답에서 발주자가 확정 수치를 회신하는 미정의 값이다. 확정 전까지 해당 AC는 판정을 보류한다.
5. 텔레메트리 이벤트 15종의 발화·파라미터 검수는 GDD 19.5.1을 정본으로 하는 별도 절에서 다루며, 본 절은 화면 표시·동작·전이만 다룬다.
6. 검수 환경: Chrome·Edge 최신 안정 버전, 키보드 단독·마우스 병용 각 1회 이상(RFP 6.8, GDD 15.7).
7. 확률 판정 AC는 시드 고정 리플레이(GDD 18.5, 19.5.3) 또는 통계 시뮬(±2%p)로 판정한다. "표시된다"는 별도 조작 없이 해당 화면에서 육안 확인 가능함을 뜻한다.

### D-1.1 타이틀 (Title)

필수 표시·동작·전이

- [ ] AC-TT-03: '프로젝트 열기' 확정 시 런 시작 전에 난이도 4단계(가편집/본편집/감독판/무압축)를 선택하며, 런 도중 난이도를 변경하는 수단이 존재하지 않는다 (GDD 6.4). MVP 단순화 — MVP는 난이도 선택 미구현(본편집 고정). 본 개발은 GDD 기준.
- [ ] AC-TT-04: 시스템 실제 시각 21:57:00~21:57:59 사이에 타이틀이 표시 중이면 빈 V2 트랙에 SOURCE_0000 클립이 1초간 나타난다 (GDD 15.1).

엣지 케이스

### D-1.4 업무 배치 (ProductionBoard)

필수 표시 요소

- [ ] AC-BD-01: 상단에 4개 제작 트랙 가로 바(현재값과 게이트 기준 병기), 좌측 인물 카드(이름·집중력·체력), 중앙 6개 업무 슬롯(명칭·주요 트랙·소모치), 우측 오늘의 촬영 조건·컨펌 일정·치명 누락이 표시된다. 이혜미가 이탈하지 않은 날은 그의 패시브에 따라 그날 첫 발생 예정 오류 1건(일정 충돌/권리·동의 누락/원본 경로 오류/납품 규격 불일치/소품·장비 누락 중 1종)이 사전 공개된다 (GDD 15.3, 8.1, 3.4, MVP).

동작 규칙

- [ ] AC-BD-02: 인물 1명당 기본 1슬롯, 슬롯당 최대 2명이며 3명째 배치 입력은 거부된다. 배치된 인물을 다시 선택하면 기존 배치가 해제된다 (GDD 8.3, MVP).
- [ ] AC-BD-03: 페어 시너지 10종은 같은 슬롯 배치가 확정되는 순간 성립을 판정한다. 3인 콤보 5종은 '하루 시작' 확정 시점에 일괄 판정하며, 콤보의 '순서'는 실시간 배치 순서와 무관하게 슬롯 정의 순서(기획·구성 → 프리프로덕션 → 촬영·현장 → 편집·모션 → 최종 납품 QC)상 해당 인물들이 콤보 명시 슬롯에 배치되어 있으면 충족으로 정의한다(발주자 확정). 성립 시 GDD 4.1·4.2의 발동 확인 문구를 원문 그대로 화면 하단 1줄 토스트로 출력한다 (GDD 4.1, 4.2).
- [ ] AC-BD-04: 개인 산출 = 해당 능력치 × (0.5 + 0.005 × min(집중력, 체력)) × 장비·시너지 보정. 컨디션 계수는 배치 시점 값을 사용하고 슬롯 소모는 산출 확정 후 적용한다. UI 표시값과 내부 계산값의 오차는 0이다 (GDD 8.2, 9.5.1, 19.5.2).
- [ ] AC-BD-05: 업무 판정 — 기본 성공, 크리티컬 10%+보정(상한 40%), 실수 5%+보정(상한 60%), 크리티컬·실수 동시 발생 시 실수 우선. 판정 난수는 `production` 스트림만 사용하며, 크리티컬·실수 발생 내역이 결산에 인물·슬롯 단위로 표시된다 (GDD 8.2, 18.5, MVP).

상태 전이

### D-2.7 결합 벡터 — 슬롯 실행 1회 분해 (TV-CMB-01)

정본(GDD 9.5.0 모델): 슬롯 실행 1회의 트랙 증가 = Σ수행 인물 개인 산출(슬롯 주요 트랙 적립) + 카드 성공값(명시 트랙). **'개인 산출 합 + 카드 성공값'의 가산 결합 방식이 정본이다.** 본 벡터는 검산 스크립트(balance-sim-final-final-d7.py) ⓑ 균형 시나리오의 D-7 기획·구성 슬롯 실행 1회를 실제 실행값으로 분해한 것으로, 공식 ①(개인 산출)·카드 가산·패시브 전환의 결합 순서를 통째로 검증한다.

TV-CMB-01 입력(전량): D-7, 기획·구성 슬롯. 수행 인물 — 이영림(기획 10, 집중 85, 체력 75) + 허파랑(기획 9, 집중 90, 체력 80). 보정 ×1.25(페어 '브리프 잠금'+'한 문장, 한 장면' — 검산 스크립트 ⓑ 표기), 카드 성공값 기획·서사 +6·수정 부채 −2. 실행 전 상태 — 기획·서사 12.00, 관객 공감 0.00, 수정 부채 0.00.

| 단계 | 적용 내용 | 계산 | 값 |
|---|---|---|---|
| 1 | 개인 산출 — 이영림 | 10 × (0.5 + 0.005×min(85, 75)) × 1.25 = 10 × 0.875 × 1.25 | 10.9375 |
| 2 | 개인 산출 — 허파랑 | 9 × (0.5 + 0.005×min(90, 80)) × 1.25 = 9 × 0.900 × 1.25 | 10.1250 |
| 3 | 개인 산출 합 | 10.9375 + 10.1250 | 21.0625 |
| 4 | 카드 성공값 가산 | 21.0625 + 6 (기획·서사 명시 트랙) | 27.0625 |
| 5 | 이영림 패시브 — 기획 획득 20% 관객 공감 전환 | 전환량 27.0625 × 0.20 = 5.4125, 기획 잔여 27.0625 − 5.4125 | 21.6500 |
| 6 | 자원 반영 | 기획·서사 12.00 + 21.65 = 33.65 / 관객 공감 0 + 5.4125 / 부채 0 − 2 → 하한 0 클램프 | 33.65 / 5.41 / 0.00 |

## D-3. 레퍼런스 지위·금지 사항·해석 절차

본 절은 동작 레퍼런스 MVP의 계약상 지위와 문서 간 우선순위를 확정하고, 개발사의 임의 해석·임의 변경을 차단하는 금지 사항과 위반 시 처리 등급, 그리고 문서 충돌·공백 발견 시의 해석·질의 절차를 규정한다. 본 절의 모든 기준은 제3자가 예/아니오로 판정 가능한 수용 기준(AC)으로 기술한다.

### D-3.1 동작 레퍼런스 MVP의 계약상 지위

#### D-3.1.1 정의와 지위

1) 동작 레퍼런스 MVP(이하 "레퍼런스 MVP")는 발주자가 직접 구현한 수직절단 프로토타입 `문서/게임즈/최종_진짜최종_D-7/04_MVP프로토타입/index.html`(Artful-Project 저장소)을 말한다.
2) 레퍼런스 MVP는 게임 흐름(하루 8페이즈 순환)·판정 공식(컨펌·업무·담력 판정)·수치의 **실행 가능한 명세**로서 계약 문서의 일부로 편입된다. GDD 문장의 해석이 갈리는 경우 레퍼런스 MVP의 실행 결과를 발주자 의도의 1차 해석 기준으로 삼는다.
3) 단, 레퍼런스 MVP는 **완성 품질의 기준이 아니다.** 아트·연출·UI·사운드는 자리표시(placeholder) 수준이며, 일부 시스템은 D-3.1.3의 표와 같이 의도적으로 단순화되어 있다.
4) 검수 기준의 고정을 위해 계약 체결 시점의 `문서/게임즈/최종_진짜최종_D-7/04_MVP프로토타입/index.html` 사본과 파일 해시를 부속서 [부속서 번호]로 편철한다. 계약 체결 후 발주자 저장소에서 레퍼런스 MVP가 수정되더라도 검수 기준은 편철된 사본을 따른다.

#### D-3.1.2 문서 간 우선순위 (확정)

### D-3.3 해석·질의 절차

#### D-3.3.1 절차 (확정)

1) 발견·질의 의무: 개발사는 GDD·발주서·레퍼런스 MVP·본 부속서 사이의 충돌 또는 명세 공백을 발견한 경우, 임의 해석으로 구현을 진행하지 않고 **발견 시점부터 48시간 이내** 이슈 트래커(발주서 8.4)에 서면 질의를 등록한다. 질의에는 충돌·공백의 위치(문서·장·절), 쟁점, 개발사의 해석안(복수 가능)을 기재한다.
2) 회신 기한: 발주자는 질의 등록일 다음 영업일부터 **[2]영업일 이내** 서면(이슈 트래커 포함)으로 해석을 확정 회신한다.
3) 정본화: 확정 회신은 질의응답 로그로 축적하여 부속서 [부속서 번호] 「질의응답 로그」로 편철하며, GDD의 보충 정본으로서 이후 검수 기준에 포함된다(발주서 11.5). 회신이 GDD 본문과 충돌하는 경우 회신이 우선하되, 발주자는 차기 GDD 버전에 반영한다.
4) 임의 구현의 책임: 질의 없이 임의 해석으로 구현한 부분이 발주자 해석과 다른 것으로 확인되면, 재작업 비용은 개발사 부담으로 하고 재작업 기간은 지체 일수에 산입한다.
5) 지연의 면책: 발주자가 2항의 회신 기한을 도과한 경우, 도과일부터 회신일까지의 기간과 그로 인한 후속 일정 영향은 개발사의 지체 일수에서 제외하며 지체상금 산정에서 배제한다(발주서 5.4.3·11.5.2). 회신 지연 중 해당 쟁점 부분의 작업 보류는 개발사 귀책이 아니다.
6) 불이익 금지: 질의의 건수·빈도는 게이트 판정, 대금 지급, 개발사 평가의 불이익 사유가 되지 않는다. 질의가 집중되는 명세 구간은 발주자가 GDD 보강으로 대응한다.

#### D-3.3.2 수용 기준

- [ ] AC-QNA-01: 최종 검수 시점 기준, 문서 충돌·공백에 대한 개발사 질의 전 건이 이슈 트래커에 등록되어 있고, 각 질의의 등록 시각이 개발사가 소명한 발견 시점부터 48시간 이내이다.

- [ ] AC-QNA-04: 발주자 회신 기한([2]영업일) 도과 건은 건별로 도과 기간이 기록되어 있고, 해당 기간이 개발사 지체 일수·지체상금 산정에서 제외되어 있다.

## D-4. 아트·사운드·연출 검수 기준

본 절은 GDD v4.0 15~16장(및 11.1, 19.5.2)의 아트·사운드·연출 명세를 검수 가능한 수용 기준으로 변환한 것이다. 발주서 본문 2.2(아트·사운드 과업), 3.1(인도물 6·7번), 7.4(접근성 10종), 7.5(광과민성 안전)와 함께 적용한다.

공통 판정 규칙

1. 모든 AC는 검수 대상 빌드의 실행 화면·실행 음성으로 판정한다. 원본 작업 파일(PSD·스템)은 보조 증빙이다.
2. 시간값 판정은 검수용 화면 녹화([60fps 이상, 계약 전 확정])의 프레임 카운트로 한다. 별도 명시가 없는 한 시간 허용 오차는 본 절 각 표의 값을 따른다.
3. 색상값 판정은 무보정 스크린샷의 픽셀 스포이드 값으로 한다. 색상 토큰의 정본은 Phase 0 '아트 스타일 시안' 승인 시 확정하는 토큰표([문서번호 확정 예정])이며, 확정 전까지는 동작 레퍼런스 MVP(`문서/게임즈/최종_진짜최종_D-7/04_MVP프로토타입/index.html`)의 CSS 토큰을 기준값으로 한다.
4. GDD에 수치가 없는 항목은 '존재·상태·순서'의 예/아니오로 판정하며, 검수자의 미감 평가는 판정 근거가 될 수 없다.
5. 육안 식별·구분에 의존하는 판정 항목(AC-VIS-02·03·04·08·11, AC-STY-01·03·04·07·08·09, AC-CHR-02·03·07, AC-PSN-01·02·03·04·05·06, AC-UI-04·11, AC-ACC-06)은 판정단 3인 중 2인 이상 합의 시 합격으로 한다. 판정단 구성은 발주자 지정 3인으로 하며, 그 외 계측·대조 기반 항목에는 본 규칙을 적용하지 않는다.

전제: 렌더링 문법의 정본은 아트 발주서 2.7이며, 기준 방향은 2010~2020년대 일본 세이넨 만화 원작 TV 애니메이션의 작화 문법(플랫 셀 음영, 굵기 불균일 잉크선, 저채도, 미화되지 않은 평범한 얼굴, 필름 그레인)이다. 본 소절의 각 AC는 다른 항목을 전부 충족하더라도 위반 시 단독 불합격 사유가 된다. 적용 범위는 캐릭터·배경·카드 일러스트·UI 일러스트 전 계열이며, UI 아이콘·테두리 프레임은 축소 시인성을 위해 AC-STY-01의 테이퍼 규정을 완화할 수 있으나 AC-STY-02·05·06은 예외 없이 적용한다(아트 발주서 2.7 적용 예외).

- [ ] AC-STY-01: 라인워크가 시작·끝이 가늘어지는 테이퍼 잉크선이며, 굵기가 1920×1080 기준 외곽선 3~5px·내부 디테일선 1.5~2.5px 범위다. 전 구간 균일 굵기의 벡터선은 불합격 (아트 발주서 2.7-1).
  - 판정: 무보정 스크린샷을 200% 확대하여 한 선 안에서 굵기 변화가 육안으로 확인됨을 보고 합격 판정한다. 판정단 3인 중 2인 이상 합의 시 합격. 외곽·내부 선 굵기값은 확대 상태의 픽셀 계측으로 병행 확인한다.
- [ ] AC-STY-02: 음영이 플랫 셀 방식으로, 베이스 1톤 + 그림자 1톤(복잡한 부위만 최대 2톤)이며 그림자 경계가 하드 엣지다 (아트 발주서 2.7-2).

- [ ] AC-STY-03: 인물 윤곽을 따라 흐르는 림라이트, 블룸·렌즈플레어, 피부·머리카락의 광택 하이라이트가 존재하지 않는다 (아트 발주서 2.7-2).

- [ ] AC-STY-04: 얼굴 작화가 캐치라이트(눈 반짝임) 없음 · 눈 밑 그늘 존재 · 기본 표정 무표정(deadpan)의 3요건을 모두 충족한다 (아트 발주서 2.7-3).

#### D-4.2.1 성격의 시각 문법 — 5채널 (AC-PSN)

전제: 아트 발주서 2.7-3(캐치라이트 금지·기본 무표정)이 표정 연기를 원천적으로 제한하므로, 인물의 성격은 표정이 아니라 5채널(① 실루엣 ② 상시 소품 ③ 버릇 동작 ④ 주변 환경 ⑤ 밤의 왜곡)로만 전달한다. 본 소절은 그 5채널이 실제 납품 그림에 구현됐는지를 판정하며, 대조 정본은 아트 발주서 2.4-6의 인물별 표다. 판정 대상은 실명 4인(허파랑·이영림·이혜미·손미림)이며, 플레이어는 기존 캐논 유지로 본 소절의 신설 판정 대상이 아니다(①은 AC-CHR-02·03에서 판정하므로 본 소절에서 중복 판정하지 않는다).

- [ ] AC-PSN-01: 실명 4인 각각의 상시 소품이 캐릭터 시트·탑다운 스프라이트·초상 전 계열에 일관되게 등장한다 — 계열별로 해당 인물의 상시 소품이 1종 이상 식별되고, 계열 간 동일 소품의 형태·색이 상충하지 않는다 (아트 발주서 2.4-6 표 ② 열).
  - 판정: 인물별로 2.4-6 표 ② 열의 소품 목록과 시트·스프라이트·초상 납품본을 대조하여, 3계열 각각에서 소품 1종 이상을 지목하고 계열 간 형태·색 상충 0건이면 합격 판정한다. 4인 중 1인이라도 소품 0건인 계열이 있으면 해당 인물 불합격. 판정단 3인 중 2인 이상 합의 시 합격.
- [ ] AC-PSN-02: 인물별 버릇 동작이 해당 인물의 업무 애니메이션 키프레임에 1종 이상 포함된다 — 허파랑 화면 돌려 보여주기 / 이영림 폰 각도 확인 / 이혜미 라벨 프린터 강타 / 손미림 옷깃 정리 (아트 발주서 2.4-6 표 ③ 열).

- [ ] AC-PSN-03: 인물별 주변 환경 요소가 해당 인물의 자리를 포함한 배경 에셋에 존재한다 (아트 발주서 2.4-6 표 ④ 열).

### D-4.7 본 절의 판정 운용

1. 본 절 AC의 검수 시점: D-4.1~D-4.2는 게이트 2(콘텐츠 알파)부터, D-4.3~D-4.5는 게이트 2부터 존재·게이트 3에서 수치 판정, D-4.6은 게이트 3(베타)에서 전수 판정하며, 최종 검수에서 전 항목을 재확인한다.
2. 불합격 항목은 발주서 4.4의 판정 3단계(통과/조건부 통과/NO-GO) 절차에 따라 처리하며, 본 절에 없는 항목을 이유로 한 판정은 불가하다(발주서 4.4.3).
3. 본 절과 GDD 수치가 상이할 경우 GDD v4.0을 정본으로 하고, 본 절은 지체 없이 개정한다.
