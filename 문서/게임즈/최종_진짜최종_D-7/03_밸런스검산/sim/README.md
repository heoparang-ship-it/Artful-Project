# 《최종_진짜최종: D-7》 시뮬레이션 코어 레퍼런스 구현

GDD v4.0 18.1이 규정한 **엔진 독립 시뮬레이션 코어**의 실행 가능한 레퍼런스 구현이다.
발주서(DEV-RFP-FINAL-FINAL-D7.md) 6.2·6.3·6.4와 7.2의 검수 항목을 이 코드로 대조한다.

- 정본 기획: `../../01_기획서/FINAL-FINAL-D7-GDD.md`
- 검수 기준: `../../02_발주서/DEV-RFP-ACCEPTANCE-SPEC.md`
- 기준값 재현 스크립트(정본): `../balance-sim-final-final-d7.py`

## 1. 실행 방법

의존성 0. Node.js 18 이상이면 설치·빌드 없이 바로 실행된다.

```
cd 문서/게임즈/최종_진짜최종_D-7/03_밸런스검산/sim

node balance.mjs          # GDD 9.5 표준 7일 시뮬 3종 실행 + 정본 기준값 대조
node balance.mjs --json    # 결과 JSON만 출력 (CI 파싱용)
node test.mjs              # 시드 고정 자동 테스트 6종 전체
node test.mjs 3 6          # 지정한 번호만 실행
```

두 명령 모두 실패 시 exit code 1을 반환한다. 성공 시 0이다.

### 정본 대조

```
python3 ../balance-sim-final-final-d7.py > py.txt
node balance.mjs | head -33 > js.txt
diff py.txt js.txt          # 차이 0행
```

`balance.mjs`의 표준출력 33행은 파이썬 정본과 **바이트 단위로 일치**한다.
내부 자원값도 double 비트 단위까지 동일하다(`repr` 대조 확인 완료).

| 라인 | 재현 기준(발주서 6.3-2) | 본 구현 실측 |

| ⓐ 무계획 | 4트랙 전원 미달, 참고 점수 57.1 ±0.1 | 57.07 (게이트 4항 전부 ×) |

**검수 절차.** 개발사 TypeScript 코어의 헤드리스 러너에 동일 입력(배치 스케줄·훅·전제)을 주고,

소수점 처리·클램프 순서까지 GDD 9.5.1 전제를 따라야 같은 값이 나온다.
값이 어긋나면 `node balance.mjs --json`의 트랙·자원 스냅숏으로 어느 단계에서
갈라졌는지 특정한다.

### 3.4 AC-MEM-06 · AC-MEM-08 판정 방식

⑥번 테스트는 AC-MEM-06의 다섯 항(㉠~㉤)을 그대로 검사한다.
핵심은 **두 카운터가 분리되어 있는지**다(AC-MEM-08 단서 3).

- IT-28·IT-29 획득 횟수 상한(각 런 2회) → 상한 도달 시 잔여 일차 재스폰 차단
- 밈 레이어(OF-21~30 / IT-31~38 / GH-16~19) 통산 상한(커피 +2 / 간식 +2)

두 카운터를 합산하거나 상호 차감하는 구현은 불합격이다. 또한 획득 1회는
**인벤토리 최초 편입 시점** 기준이므로, 드롭 후 재획득 시 카운터가 증가하지 않고
자원도 재지급되지 않아야 한다(AC-MEM-08 단서 6). `applySupplyGain`의 `instanceId`가
이 판정을 담당한다.

## 4. 구현 시 주의한 지점 (개발사 인계 사항)

1. **부동소수 재현성.** 개인 산출 합산 순서(멤버 배열 순서)와 평균 집중력 합산 순서
   (인물 정본 순서 HP→YL→HM→MR→PL)를 바꾸면 하위 비트가 달라져 92.44가 재현되지 않는다.
2. **클램프 시점.** 트랙 상한 100은 각 적립마다 적용한다. 누적 후 일괄 적용하면 값이 달라진다.
3. **컨디션 계수 고정.** 그날 아침(배치 시점) 값으로 고정하고, 슬롯 소모는 산출 확정 후 적용한다(9.5.1).
4. **이면 조우율 클램프 차이.** 정본 파이썬은 0~100, `core.mjs`는 GDD 확정치인 5~95를 쓴다.
   ⓐⓑⓒ 전 구간의 원값은 20~66이라 결과가 동일하며, `balance.mjs`가 매 일차 원값이
   5~95를 벗어나지 않는지 단언해 이 전제를 지킨다. 벗어나면 즉시 예외를 던진다.
5. **하한 클램프 5는 미발동 구간.** 6.2의 감산 항은 '무결성 80 이상 −10%p' 하나뿐이므로
   도달 가능한 최소 원값은 가편집 22 − 10 = **12**다. 하한 5는 방어적 클램프다.
6. **RNG 스트림 핸들 재취득.** 세이브 로드로 RNG 인스턴스가 교체되면, 로드 이전에 받아 둔
   스트림 핸들은 폐기된 인스턴스의 카운터를 소비한다. 페이즈 경계를 넘은 뒤에는 반드시
   핸들을 다시 받아야 한다. ⑤번 테스트가 이 결함을 검출한다.
7. **②번 테스트의 시행 설계.** n=1,000·p≈0.6이면 표준오차가 1.55%p라 ±2%p 기준이
   표집 잡음보다 좁다. GDD의 '1,000회'를 배치 단위로 유지한 채 고정 시드 20배치
   (총 20,000회)의 누적으로 판정하고, 배치별 최대 편차도 함께 출력한다.
